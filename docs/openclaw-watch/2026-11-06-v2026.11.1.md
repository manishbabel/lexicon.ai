## What's notable

### 1. Cron catch-up after restart
Scheduler records a `last_run` watermark and replays any jobs whose window was missed during downtime. Simple and high-impact for agents that need temporal guarantees (e.g. daily digest, monitoring loops).

### 2. Gateway streaming buffer fix
The streaming layer was accumulating partial tag lookahead and stalling. The fix applies a bounded lookahead window so the stream flushes even when tool-call-like patterns appear mid-token. Lexicon's gateway does the same streaming and likely has the same latent bug.

### 3. Subagent session continuity
The runtime now carries a `session_ref` opaque token so follow-up messages from the orchestrator can reach the same logical subagent after a model change or restart. This directly addresses dropped context in multi-step tasks.

### 4. PostgreSQL-backed state with migrations
Replaces ephemeral or file-backed memory/state with a proper relational store and version-tracked schema migration. Unlocks multi-process and multi-instance deployments.

### 5. Decision routing + media-capable models
The router gained a signal-based tier selector: a lightweight classifier chooses the cheapest model sufficient for the input (text-only vs. media), deferring to a media-capable model when needed. Pairs well with Lexicon's existing LLM router.

## My picks for what to spike next

### Spike 1 — Cron catch-up (`src/cron/scheduler.py`, `src/cron/store.py`)
`store.py` already persists job definitions; adding a `last_run` column and a startup sweep for missed windows is a small diff with a real reliability gain. This is a one-afternoon change.

### Spike 2 — Gateway streaming lookahead (`src/gateway/session.py`)
Add a bounded partial-tag lookahead buffer to the streaming path so chunks flush even when mid-stream content looks like an opening XML/HTML tag. Prevents user-visible stalls on tool calls.

### Spike 3 — Model-tier decision routing (`src/engine/llm/router.py`)
Lexicon already has a router; extend it with a capability signal (text-only vs. media) and a cheapest-sufficient heuristic. This pairs with the existing `claude_provider.py` / `openai_provider.py` split.
