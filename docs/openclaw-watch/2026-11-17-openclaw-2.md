## What's notable

### 1. Restart-safe conversation queues (2026.8.1 + 2026.11.5)
Queued messages, send permissions, and final chat writes now survive Gateway restarts. Graceful shutdown holds when restart intent stalls. Failed Doctor or Gateway startup rolls back an activated update automatically. This closes the class of bugs where a mid-turn restart drops a queued user message silently.

### 2. Grounded dreaming — background memory consolidation with provenance (2026.8.1)
Memory consolidation runs as a background process. Every promoted item carries provenance links back to the contributing session(s), and a Dream Diary log records each consolidation event. Incognito threads flush on restart and are excluded from consolidation. This turns memory from a write-once store into a living, traceable graph.

### 3. CPU-scaled agent concurrency (2026.8.1)
Default top-level agent concurrency scales with CPU count, bounded between 8 and 16 runs. Explicit limits are preserved and take precedence. This prevents both under-utilisation on large boxes and queue flooding on small ones.

### 4. Private credential request flow (2026.8.1)
Agents can request a named secret through a masked prompt so the value never enters chat history or model context. An optional proxy gate restricts substitution to a declared allowlist of egress destinations. Credential values in vault writes were already masked in Lexicon, but the agent-side request flow and destination binding are new patterns.

### 5. Conversation-bound automation context (2026.8.1)
Scheduled jobs created during an agent turn now default to the originating conversation's context rather than running fully isolated. API and CLI-created jobs stay isolated. This is a default-to-context pattern that reduces the "where did this cron output go?" confusion for user-initiated automations.

## My picks for what to spike next

**1. CPU-scaled concurrency** (`src/engine/orchestrator.py`) — one-liner change, immediate benefit on multi-agent workloads. The queue already has configurable caps; just wire `os.cpu_count()` into the bounds.

**2. `maxSummaryChars` in compactor** (`src/engine/context/compactor.py`) — one config constant prevents unbounded compaction digests from bloating the system prompt across long meetings. Low risk, proven pattern.

**3. Restart-safe queue persistence** (`src/engine/queue.py`) — the highest-impact change. Currently all in-memory queue state is lost on restart. Even a lightweight SQLite write of pending lane entries at enqueue time (and a drain on startup) would eliminate dropped-message bugs for long-running Lexicon sessions.
