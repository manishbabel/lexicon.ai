## What's notable

### 1. Gateway crash-loop → stable repair path
`v2026.7.1` headline fix: a repeatedly-failing Gateway now enters a repair path with structured backoff instead of restarting indefinitely. The repair path emits structured diagnostics and allows operator intervention before resuming.

### 2. Provider fallback chain with session retention
`v2026.6.34` extended-stable adds first-class provider fallback ordering: if the primary LLM provider fails mid-session, the runtime promotes a secondary without losing session state. Combined with retained sessions, this eliminates the cold-restart cost on provider timeouts.

### 3. Memory checkpoint system
Session groups, goals, and context now write lightweight checkpoints that survive process restarts. Legacy-index conflicts (patch 2026.7.1-1) are repaired on startup rather than blocking boot.

### 4. Credential sanitization in runtime diagnostics
`v2026.6.34`: operator-facing diagnostics now redact token/secret fields before logging. The scrubbing runs at the structured-log layer, not at call sites, so new fields are automatically covered.

### 5. Durable channel delivery (beta preview)
`v2026.7.2-beta.6`: messages queued to channels (Slack, Telegram, Discord, etc.) survive gateway restarts. The delivery queue is persisted and replayed on reconnect, eliminating silent drops on network partition.

## My picks for what to spike next

1. **Provider fallback chain** (`src/engine/llm/router.py`) — lowest effort, immediate resilience gain. `router.py` already abstracts providers; adding a fallback list and promotion logic is additive. Spike: add `fallback_order: list[str]` config + catch on provider error → rotate.

2. **Gateway crash-loop protection** (`src/gateway/server.py`) — medium effort but the risk of an unbounded restart loop in production is high. Spike: add a consecutive-failure counter with exponential backoff and a `GATEWAY_REPAIR` state that logs diagnostics and pauses before retrying.

3. **Credential sanitization** (`src/shared/logger.py`) — low effort, compliance/security hygiene. Spike: implement a `_scrub()` pass on structured log payloads that redacts fields matching a configurable denylist (token, secret, key, password, credential).
