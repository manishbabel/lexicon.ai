## What's notable

### 1. Fail-closed security hardening (2026.6.6)
Transcript, sandbox, MCP, browser, channel, and execution-approval paths now **fail closed** rather than open around unsafe access, timed-out approvals, and malformed boundary input. Companion changes protect env-var injection, git protocol controls, and build-tool overrides. The pattern: any code path that gates privileged execution treats an error/timeout as a deny, not a pass-through.

### 2. SQLite migration for persistent state (2026.6.1, 2026.6.5)
OpenClaw systematically replaced JSON file stores with SQLite across auth profiles, device-pair state, ACP process state, memory dreams, sandbox registry, plugin dedupe, session metadata, cron jobs, and Matrix sync caches. The driver was concurrent access reliability — JSON file rewrites under concurrent reads/writes produce SQLITE_BUSY failures and torn reads. Doctor preflight now migrates legacy JSON stores before runtime init.

### 3. Event-driven `on-exit` cron triggers (2026.7.1-beta.2)
A new `on-exit` schedule type watches a command/process and wakes an agent when it exits, rather than at a wall-clock time. Companion: **detached session runs** — session-targeted cron jobs execute without blocking the parent session. Together these enable reactive automation (e.g., "run memory consolidation when the recording session exits") that purely time-based schedulers cannot express.

### 4. Credential-scoped dynamic model routing — ClawRouter (2026.7.1-beta.2)
ClawRouter ships as a bundled provider plugin with **credential-scoped dynamic model discovery**, OpenAI-compatible and native Anthropic/Gemini transports, and managed budget reporting. The key departure from static config-driven routing: available models are discovered at runtime from the credential, not enumerated in config, and budget/quota is tracked per-route.

### 5. Scoped conversation capability profiles (2026.7.1-beta.2)
Per-conversation **capability profiles** prepare tool and access boundaries before the turn begins, without weakening global defaults. The effect: a conversation can be granted narrower or broader tool access than the agent's default, and that scope is enforced through the session lifetime rather than per-call.

## What we can use in Lexicon

Ranked by value/effort. All paths verified to exist in the repo.

| # | Pattern | Value | Effort | Lexicon target |
|---|---|---|---|---|
| 1 | SQLite cron store | High | Low | `src/cron/store.py` |
| 2 | Fail-closed execution paths | High | Medium | `src/gateway/server.py`, `src/engine/runtime.py` |
| 3 | `on-exit` cron trigger type | Medium | Medium | `src/cron/scheduler.py`, `src/cron/store.py` |
| 4 | Scoped session capability profiles | Medium | Medium | `src/gateway/session.py` |
| 5 | Dynamic model routing with quota | Medium | High | `src/engine/llm/router.py` |

**1. SQLite cron store — `src/cron/store.py`**

`CronJobStore` currently reads and writes `~/.lexicon/cron/jobs.json` with a full-rewrite pattern on every `upsert()` and `update_state()`. Under concurrent cron fires (two jobs triggering within the same second) this produces torn writes and stale reads. `update_state()` calls `load()` + full `save()` every time a job completes — O(n) on every state flush.

Replace with SQLite: one `jobs` table (definition columns) + one `job_state` table (mutable runtime columns). `update_state()` becomes a single `UPDATE` on the state table. Doctor preflight migrates the JSON file on first run.

**2. Fail-closed execution paths — `src/gateway/server.py`, `src/engine/runtime.py`**

Review every `except Exception: pass` and `except Exception: return None` on gating paths (session auth, tool approval, MCP call validation). OpenClaw's pattern: replace silent pass-throughs with explicit denies that log the reason. Particularly relevant for the `cron:fire` → `_execute_agent` path in `src/cron/scheduler.py` (line 198–204) where hook failures are currently silently dropped on privileged execution.

**3. `on-exit` cron trigger — `src/cron/scheduler.py`, `src/cron/store.py`**

`CronScheduleConfig.type` in `store.py:38` is a `Literal["at", "every", "cron"]`. Add `"on_exit"` with a `watch_command: str` field. In `scheduler.py:_build_trigger()`, handle `on_exit` by spawning an asyncio subprocess watcher rather than an APScheduler trigger. Most useful for Lexicon's recording flow: trigger memory consolidation or transcript indexing when a meeting session closes.

**4. Scoped session capability profiles — `src/gateway/session.py`**

`SessionManager.create_session()` currently creates sessions with a persona and agents but no per-session tool scope. Add an optional `capability_profile: dict[str, list[str]]` on `SessionState` that narrows which tools from `src/engine/tools/registry.py` are available. The profile is set at session creation and enforced by `AgentRuntime` before dispatching tool calls. Useful for read-only research sessions vs write-capable coding sessions.

**5. Dynamic model routing — `src/engine/llm/router.py`**

`PersonaLLMRouter.resolve()` falls back through persona config → `default_llm_provider` → raises if nothing is set. No quota awareness. ClawRouter's pattern: at startup, query each configured credential for its available model list, cache that manifest, and resolve the best match at call time (rather than at config-parse time). Medium-priority — Lexicon's current static config works fine, but this matters when rotating API keys or adding OpenRouter.

## What to spike next

**Immediate: SQLite cron store** (`src/cron/store.py`)

Lowest effort, highest immediate payoff. Eliminates the torn-write race, makes `update_state()` O(1), and is the prerequisite for the `on-exit` trigger work (which needs atomic watch-state storage). The migration is mechanical: swap `json.loads/write_text` for `sqlite3` with two tables, add a `doctor_migrate()` that moves the existing `jobs.json` to the DB on first run, and the rest of `CronScheduler` is unchanged.

After that: fail-closed audit of `src/engine/runtime.py` — highest security value, and the surface is bounded.
