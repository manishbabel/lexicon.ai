## What's Notable

### 1. External Gateway Lifecycle Supervision (2026.8.1)
OpenClaw 2.0 introduced explicit external Gateway lifecycle supervision with **verified restart handoff** and **shared durable ingress monitors** for channel plugins. The Gateway process no longer assumes it owns its own restart — an external supervisor confirms handoff before traffic is re-accepted, and ingress monitors across channel plugins share durable state so in-flight messages survive restarts.

### 2. Message + Session Integrity Layer (2026.9.5)
A dedicated integrity pass ensures queued, imported, streamed, and tool-result messages are preserved across retries, hooks, recovery sequences, and channel lifecycle transitions. Previously these were at-most-once; the new model is effectively at-least-once with idempotency guards at the hook boundary.

### 3. Plugin/Skill Hot-Reload Without Gateway Restart (2026.9.5)
Supported plugins can now be installed at runtime without restarting the Gateway process. The plugin registry accepts live additions, waits for readiness, and only then routes new requests to the plugin — making zero-downtime skill updates possible.

### 4. Ephemeral Thread Mode (2026.8.1)
Incognito threads hold conversation transcripts and compaction state in Gateway memory only — never written to persistent storage, flushed on restart. Paired-node session catalogs extend this to authorize read-only remote commands without persisting credentials.

### 5. Atomic Update Pre-Check + Triage Agent (2026.9.5)
`openclaw update` now validates the next version before committing the switch. If the post-update Doctor fails, it rolls back the npm candidate, preserves configuration and secret references, and hands the failure to a **built-in triage agent** rather than leaving the Gateway in a broken state.

## What We Can Use in Lexicon

Ranked by **value / effort** (H = High, M = Medium, L = Low).

### 1. Message Integrity Across Hooks and Retries — Value: H / Effort: M
**Pattern:** Track message delivery state (queued → dispatched → acked) through the hook pipeline. Messages that fail mid-hook or during channel transitions are re-queued at the last confirmed checkpoint, not lost.  
**Where:** `src/gateway/session.py`, `src/engine/hooks/registry.py`, `src/engine/hooks/builtin.py`  
**Why now:** Lexicon's `session.py` currently drops in-flight messages on connection errors with no replay path. This is the highest-impact reliability gap.

### 2. External Gateway Supervision with Verified Restart Handoff — Value: H / Effort: M
**Pattern:** Decouple Gateway restart logic from the Gateway process itself. A supervisor (could be `src/cron/scheduler.py` or a new thin wrapper) confirms the old process has released its port and the new one is ready before routing resumes. Shared durable ingress monitors prevent duplicate message delivery during the gap.  
**Where:** `src/gateway/server.py`, `src/gateway/router.py`  
**Why now:** Lexicon's `server.py` has no graceful handoff — restarts cause a hard drop on all active WebSocket sessions.

### 3. Skill/Tool Hot-Reload — Value: M / Effort: M
**Pattern:** The tool registry accepts new registrations at runtime. A readiness probe (is the skill initialized?) gates routing. New requests go to the new skill; in-flight requests complete on the old one.  
**Where:** `src/engine/skills.py`, `src/engine/tools/registry.py`  
**Why now:** Currently adding a new tool requires a full engine restart. This is a developer-experience and uptime improvement, not a correctness fix.

### 4. Ephemeral Working Memory Mode — Value: M / Effort: L
**Pattern:** A flag on the working-memory manager that disables persistence writes. Useful for sensitive sessions or testing — all context stays in-process, flushed on shutdown.  
**Where:** `src/engine/memory/working.py`, `src/engine/memory/short_term.py`  
**Why now:** Low effort to add, directly useful for ephemeral agent tasks where you want clean-slate guarantees.

### 5. Atomic Cron/Scheduler Pre-Check — Value: M / Effort: L
**Pattern:** Before committing a scheduled job's next run, validate the handler is still available (skill/tool exists, LLM provider is reachable). If not, hand off to a recovery path rather than silently skipping or crashing.  
**Where:** `src/cron/scheduler.py`, `src/engine/runner.py`  
**Why now:** Lexicon's scheduler currently silently drops jobs when their skill handler is unavailable.

## My Picks — What to Spike Next

**Top pick: Message Integrity Across Hooks and Retries** (`src/gateway/session.py` + `src/engine/hooks/registry.py`)

This is the pattern with the most direct reliability payoff. The Lexicon gateway already has session tracking and a hooks pipeline — adding a delivery-state enum and a re-queue path is a focused spike that doesn't require restructuring. The OpenClaw approach (checkpoint at each hook boundary, replay from last acked) is well-suited to Lexicon's existing hook registry shape.

**Second pick: External Gateway Supervision** (`src/gateway/server.py`)

The restart-handoff gap is a production reliability concern. Even a minimal version — the supervisor waits for a health-check ping from the new process before updating the router — closes the most common failure mode.
