## What's notable

### 1. Grounded Dreaming — background memory consolidation loop (v2026.8.1)
OpenClaw now runs a background async task that promotes ephemeral episodic fragments into long-term memory during idle time. This decouples the write path from the query path and means the agent's retrieval quality improves passively without adding latency to active turns. The consolidation is configurable and can be suspended.

**Lexicon gap**: `src/engine/memory/manager.py` and `src/engine/memory/episodic.py` handle in-session memory but there is no idle-time consolidation pass. Memory written during a session stays in short-term until explicitly flushed.

### 2. MCP response size limits (v2026.8.2)
Parser-amplification attacks via oversized MCP tool responses are now capped at the Gateway boundary before responses reach the LLM or skill layer. This is a low-effort, high-value defence-in-depth measure that does not require changes downstream.

**Lexicon gap**: `src/gateway/protocol.py` handles MCP framing; no payload-size guard exists today. A 50–200 KB cap on tool response bodies would block the same attack class.

### 3. CPU-scaled concurrency (v2026.8.1)
Foreground run slots scale with CPU count instead of a fixed cap. OpenClaw derives a floor/ceiling from `os.cpu_count()` at startup. This is an easy win for multi-core deployments that currently hit the default 4-run cap.

**Lexicon gap**: `src/engine/runtime.py` and `src/engine/orchestrator.py` manage concurrency; the slot count appears to be a fixed constant. Deriving it from CPU count at init would cost ~3 lines.

### 4. Diagnostics credential redaction (v2026.8.2)
Before log emission, OpenClaw now runs a lightweight regex scrubber over diagnostic strings to redact tokens, API keys, and bearer strings. It is applied at the logger level so it is unconditional regardless of log verbosity.

**Lexicon gap**: `src/shared/logger.py` emits structured logs; no redaction pass exists. Adding a scrubber for common secret patterns (Bearer, `sk-`, `AIza`, etc.) is low-effort and eliminates a common credential-leak vector.

### 5. Gateway restart recovery — turn preservation (v2026.8.1-beta.4)
Admitted turns (requests accepted for processing) are now checkpointed so that a Gateway restart mid-execution does not silently drop them. The recovery path re-arms the admission deadline and resumes from the checkpoint.

**Lexicon gap**: `src/gateway/session.py` and `src/gateway/server.py` do not currently checkpoint admitted turns. A crash during an active run loses the in-flight request with no recovery path.

## My picks for what to spike next

**1. Diagnostics credential redaction** (`src/shared/logger.py`) — one-day spike.
Unconditional log scrubbing with a small regex set (Bearer tokens, `sk-*`, `AIza*`, `xoxb-*`). Zero behavioral risk; purely additive filter. Eliminates a real credential-leak class before Lexicon goes to any shared or cloud deployment.

**2. MCP response size limits** (`src/gateway/protocol.py`) — half-day spike.
Insert a size check in the MCP response deserialization path. A configurable cap (default 100 KB) with a logged truncation or rejection. Prevents a malformed or hostile tool server from blowing up the LLM context or the parser.

**3. Grounded Dreaming** (`src/engine/memory/manager.py`, `src/engine/memory/episodic.py`) — 1–2 week spike.
Background consolidation is the highest-value architectural pattern here: it decouples session speed from memory quality and makes retrieval compound over time. Worth a design session before implementation to decide whether to use a timer-based trigger or idle-detection via the cron scheduler (`src/cron/scheduler.py`).
