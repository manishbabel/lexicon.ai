## What's Notable

### 1. Crash-recoverable memory with quarantine store
A quarantine store layer sits between the primary database and the live agent runtime. Corrupt or schema-mismatched data is isolated rather than crashing the process. Key mechanisms: crash-recoverable SQLite snapshots, rollback-writer snapshot recovery, schema-upgrade data-loss rejection. The agent can restart cleanly after a database failure and resume from the last good snapshot.

### 2. Durable channel delivery with dead-letter recovery
Accepted inbound messages are now crash-recoverable through a shared ingress drain. Any message that was accepted by the gateway but not yet processed survives a crash or restart and is replayed via dead-letter recovery. Covers Telegram, Signal, Slack, IRC and others. The core mechanism is a persistent queue at the ingress boundary, decoupled from the gateway's in-memory session state.

### 3. Per-job dynamic cadence for scheduling
Cron/scheduling jobs now support per-job runtime cadence overrides. Each job can adjust its own repeat interval based on runtime signals (e.g. backoff on failure, faster cadence when work is detected). Backed by the existing cron heartbeat infrastructure. The scheduler tool is renamed from "cron" to "Automations" (CLI alias retained for compatibility).

### 4. Questions/Approvals with fair queuing
Agents can now interrupt their run to ask a structured question or request a human approval — with option cards, push notifications, and a fair queue so multiple pending approvals don't starve. Approvals carry history tracking and headless (no-UI) resolution for automated pipelines. Reviewer identity is surfaced.

### 5. Session rewind and branching
Users/agents can fork a conversation at any prior message, creating a new branch. Branch state is persisted separately; queued sends on the forked branch can't corrupt the parent. Relevant for agent evaluation loops, A/B prompt testing, and recovery from bad tool calls.

## What We Can Use in Lexicon

Ranked by value/effort (high value first):

### 1. Dead-letter ingress drain — HIGH value / MEDIUM effort
**Pattern**: Persist accepted inbound messages to a durable queue before processing. On crash/restart, replay unprocessed messages from the drain.  
**Why now**: Lexicon's gateway currently holds session state in memory only; a crash drops any message that arrived mid-session.  
**Map to**:
- `src/gateway/session.py` — add a checkpoint write when a message is accepted
- `src/gateway/server.py` — add drain-replay on startup before opening new connections
- `src/engine/queue.py` — the existing queue abstraction is the right insertion point for the persistent backing store

### 2. Crash-recoverable memory snapshots — HIGH value / LOW effort
**Pattern**: Periodic SQLite snapshots of working/episodic memory with rollback-on-corrupt startup logic.  
**Why now**: If `src/engine/memory/manager.py` or the SQLite layer underneath crashes mid-write, the next startup currently sees a potentially corrupt state.  
**Map to**:
- `src/engine/memory/manager.py` — add snapshot-on-write and startup integrity check
- `src/engine/memory/working.py` — scope snapshot granularity to working memory flushes
- `src/engine/memory/episodic.py` — extend to episodic store (higher value, slower churn)

### 3. Per-job dynamic cron cadence — MEDIUM value / LOW effort
**Pattern**: Each scheduled job carries a mutable `cadence` field that the job itself can update at completion (e.g. back off 2× on failure, reset on success).  
**Why now**: Lexicon's cron scheduler runs fixed-cadence jobs; no backoff or adaptive pacing on failure.  
**Map to**:
- `src/cron/scheduler.py` — extend `Job` with a `cadence_override` field, apply after each run
- `src/cron/store.py` — persist cadence overrides across restarts
- `src/cron/defaults.py` — define default backoff policy

### 4. Fair-queue approvals / structured agent questions — MEDIUM value / HIGH effort
**Pattern**: Before executing a high-risk tool call, an agent enqueues an approval request. A fair queue ensures FIFO resolution; headless mode auto-approves in CI/batch contexts.  
**Why now**: Lexicon has no interrupt-to-ask mechanism — risky tool calls execute immediately.  
**Map to**:
- `src/engine/runtime.py` — intercept tool dispatch, check if tool is approval-gated
- `src/engine/queue.py` — add an approval lane alongside the existing job queue
- `src/gateway/router.py` — route approval responses back to the waiting agent

### 5. Session branching from episodic memory — LOW value / HIGH effort
**Pattern**: Fork an agent session at a historical message; both branches write to separate episodic stores.  
**Why now**: Useful for eval harnesses and prompt regression testing, not for production agent flows yet.  
**Map to**:
- `src/engine/memory/episodic.py` — add `fork(from_message_id)` that deep-copies the store up to that point
- `src/engine/memory/transcript_index.py` — maintain per-branch index

## My Picks to Spike Next

1. **Crash-recoverable memory snapshots** (`src/engine/memory/manager.py`) — lowest effort for highest reliability gain. Can be a single PR: add a `snapshot()` call on flush and a `validate_or_restore()` on startup.

2. **Dead-letter ingress drain** (`src/gateway/session.py` + `src/engine/queue.py`) — the most impactful reliability gap. A spike to prove out the durable queue backing store would derisk the full implementation.
