## What's Notable

**1. Provider response body caps (2026.6.35)**
All provider, embedding, channel, and search integrations now cap response body reads before any processing. This is a security-correctness pattern: an uncapped read on a hostile or oversized payload can exhaust worker memory silently. The cap goes at the integration boundary, not at the consumer.

**2. Safe-update staging via isolated candidate state (2026.9.3)**
Before activating a core or plugin update, OpenClaw rehearses it in a candidate copy of the live state. Failed rehearsals abort without touching live. This pattern generalises to any hot-reload scenario where partial application would be worse than no application.

**3. Memory qualification gates (2026.9.4)**
Short-term notes now need a confirmed distinct recall query before promoting to long-term memory. Without this gate, repeated background scans inflate long-term storage with low-signal ephemera. The gate is a lightweight pre-promotion check, not a rewrite of the storage layer.

**4. Cron intent persistence across restarts (2026.9.3)**
Scheduled delivery intent is written durably before execution begins, and recovered on restart. This separates intent (what should run, when) from execution (whether it ran), making the scheduler resilient to mid-flight crashes without requiring distributed transactions.

**5. Runtime context stripping at the gateway boundary (2026.9.3)**
The gateway distinguishes user-authored input from injected runtime context and strips internal markers before handing the message to channel reasoning previews. This prevents internal scaffolding from leaking into outbound reasoning or being reflected back in channel responses — a privacy and fidelity issue.

## My Picks — Spike Next

**Spike 1: Provider response body caps (`src/engine/llm/provider.py`)**
Pure safety improvement with no behaviour change in the normal case. Implement a `read_limited(response, max_bytes=8*1024*1024)` wrapper in the base `LLMProvider` class and apply it across all provider implementations. Extend the same wrapper to the three network-fetching tools. Low risk, addresses a real memory-exhaustion vector.

**Spike 2: Memory qualification gate (`src/engine/memory/manager.py`)**
Before the episodic→long-term promotion step in `manager.py`, require that the note's key has appeared in at least one distinct external recall query (not just internal scans). Store a `recall_count` field in `episodic.py`. Prevents the background summariser from inflating long-term storage with scan noise, keeping memory retrieval signal-clean.
