## What's Notable

**1. Crash-recoverable state with rollback-writer + quarantine stores (2026.7.2-beta.5)**
Persisted data gets a quarantine store before writes commit; SQLite snapshots are taken at checkpoints; a rollback-writer restores from the last clean state on crash. Pattern: write-ahead guard → checkpoint → quarantine → promote. Applicable wherever Lexicon persists memory or cron state to disk.

**2. Per-job dynamic cron cadence (2026.7.2-beta.5)**
Each scheduled job can adjust its own next-fire interval at runtime based on outcome — back off on failure, accelerate on finding new content, etc. Replaces static schedule entries with a per-job cadence value returned from the job itself. Direct analogue to Lexicon's recurring tasks.

**3. Conversation forking / transcript branching (2026.7.2-beta.5)**
Users fork a conversation from any past message, creating a branching transcript tree. Sessions track a `branch_id` + `parent_message_id`; UI presents parallel branches side by side. Enables "try a different angle" without losing the original thread — valuable in multi-agent orchestration for checkpoint retries.

**4. Gateway self-healing repair path (2026.7.1)**
Rather than restart-looping on consecutive failures, the gateway enters a quarantined "repair mode": stops accepting new connections, drains in-flight work, emits a health-unhealthy signal, attempts a single clean restart. If restart succeeds, traffic resumes; otherwise stays drained and alerts.

**5. Dead-letter recovery for durable channel ingress (2026.7.2-beta.5)**
Channel messages are written to a dead-letter queue before delivery; on gateway restart, the dead-letter is replayed. Prevents message loss during planned or unplanned restarts. Especially relevant for async inbound channels.

## What We Can Use in Lexicon

Ranked by value/effort. Every path below is verified to exist in the repo.

### 1. Per-job dynamic cadence — `src/cron/scheduler.py` ★★★ Value / ★ Effort

Have each cron job return a `next_interval_seconds` (or `None` for default). The scheduler reads it after execution and re-enqueues accordingly. `src/cron/scheduler.py` and `src/cron/store.py` already manage job lifecycle; adding a return-value contract is a small, additive API change. Immediate benefit: Lexicon's blog-monitor and openclaw-watch recurring tasks can back off when nothing is new and speed up when activity is detected.

### 2. Secret redaction in LLM provider layer — `src/engine/llm/provider.py` ★★★ Value / ★ Effort

A `redact(text)` helper that strips tokens, API keys, and credential patterns, applied before any log statement in `src/engine/llm/provider.py`, `src/engine/llm/claude_provider.py`, `src/engine/llm/openai_provider.py`, and `src/engine/llm/litellm_provider.py`. Pure safety win: no behavioral change, no tradeoffs, ships alongside any provider change.

### 3. Crash-recoverable memory snapshots — `src/engine/memory/manager.py` ★★★ Value / ★★ Effort

Add a lightweight checkpoint before and after writes in `src/engine/memory/manager.py`. On startup, validate the last checkpoint; restore from the previous one if corrupt. `src/engine/memory/episodic.py` and `src/engine/memory/working.py` hold the actual stores and are the write targets. Moderate effort — needs a snapshot path and checkpoint protocol, but no schema migrations.

### 4. Gateway repair-path on repeated failures — `src/gateway/server.py` ★★ Value / ★★ Effort

Replace restart-loop with: count consecutive failures → threshold → drain → single restart attempt → alert if still failing. `src/gateway/server.py` is the right hook. Needs a failure counter and a two-state health machine (healthy / repair). `src/gateway/router.py` would surface the health-unhealthy signal to upstream callers.

### 5. Transcript branching — `src/engine/memory/transcript_index.py` ★★ Value / ★★★ Effort

`transcript_index.py` already indexes transcripts. Branching adds a `parent_message_id` FK and a `branch_id` per session, plus fork-at-offset logic. Higher effort but aligns with Lexicon's multi-agent orchestration — agents could retry a subtask from a checkpoint without losing the parent session context.
