## What's notable

### 1. Quarantine store + crash-recoverable snapshots (beta.7)
SQLite snapshots are now promoted to first-class recovery artefacts: a separate quarantine store survives primary-database damage and lets the agent resume without replaying the full journal. The pattern decouples durability from the main write path.

### 2. Per-job dynamic cadence + heartbeat-task conversion (beta.7)
Static cron expressions gain an adaptive layer: each job can self-report a preferred next-fire time, and heartbeat monitors can be promoted to full-weight scheduled tasks (or demoted back). Scheduling becomes a runtime concern, not a config concern.

### 3. Shared ingress drain + dead-letter recovery (beta.7)
Nine channel adapters now share a single ingress drain with a dead-letter queue. Messages that fail delivery are held durably and retried on gateway restart rather than being silently dropped. The drain is channel-agnostic—each adapter just enqueues; the drain owns ordering and retry policy.

### 4. Session checkpoints + recovery paths (7.1)
Sessions carry an explicit checkpoint concept: a point-in-time snapshot of goals, context state, and unread markers that can be branched or rewound. Recovery paths let a session self-heal after a crash by replaying from the last checkpoint rather than starting cold.

### 5. Ticketed MCP app host (beta.7)
MCP tools are now hosted in bounded "ticket" contexts—each invocation gets its own resource envelope (bound tools, bounded context budget, resource manifest) rather than sharing a global tool namespace. Interactive dashboards surface pinned app state without leaking cross-tool context.

## What we can use in Lexicon

Ranked by value / effort (↑ = better). All paths verified to exist.

| # | Pattern | Value | Effort | Lexicon file(s) |
|---|---|---|---|---|
| 1 | **Per-job dynamic cadence** | High | Low–Med | `src/cron/scheduler.py`, `src/engine/runner.py` |
| 2 | **Cross-conversation default recall** | High | Med | `src/engine/memory/episodic.py`, `src/engine/memory/manager.py` |
| 3 | **Dead-letter gateway drain** | High | Med–High | `src/gateway/router.py`, `src/gateway/session.py` |
| 4 | **Quarantine store / snapshot recovery** | High | High | `src/engine/memory/manager.py` |
| 5 | **Ticketed MCP tool sandboxing** | Med | High | `src/engine/tools/registry.py`, `src/engine/skills.py` |

**#1 — Per-job dynamic cadence** (`src/cron/scheduler.py`): The scheduler currently uses fixed intervals from `src/cron/defaults.py`. Adding a `next_fire_hint` callback per job (returning `None` for "use default") would make heartbeat probes adaptive with minimal interface change. Heartbeat promotion maps cleanly onto the existing `runner.py` run-loop.

**#2 — Cross-conversation recall** (`src/engine/memory/episodic.py`): Episodic memory already stores per-session traces. Enabling cross-session recall by default (scoped by workspace identity) would let the agent surface relevant past context without explicit recall commands. `manager.py` is the right place to wire the recall-on-init path.

**#3 — Dead-letter gateway drain** (`src/gateway/router.py`): The router dispatches messages but has no retry envelope. A thin `DeadLetterQueue` backed by `src/cron/store.py` (already a persistence layer) would give durable retry without a new dependency. Session restart logic in `session.py` would drain the queue on reconnect.

**#4 — Quarantine snapshot** (`src/engine/memory/manager.py`): Snapshot the in-memory working store to a sidecar file on each commit; on startup, prefer sidecar if primary DB is unreadable. Low-risk addition to the existing `short_term.py` / `working.py` flush path.

**#5 — Ticketed MCP sandboxing** (`src/engine/tools/registry.py`): Each tool invocation could carry a `ToolTicket(budget, bound_tools)`. Adds isolation but requires threading the ticket through `skills.py` dispatch—non-trivial interface change.
