## What's Notable

1. **Gateway circuit-breaker pattern** (2026.7.1): Detecting consecutive failures and entering a named repair mode (rather than looping) is a concrete, copy-able pattern for any long-running gateway process. The key is tracking failure count + timestamp and exposing a repair-mode flag that upstream health checks can observe.

2. **Secret egress host binding** (2026.8.1-beta.2): Declare allowed outbound hosts per agent/tool at registration time; the gateway layer enforces it. This is the cleanest runtime egress-control pattern OpenClaw has shipped — straightforward to adapt for Lexicon's tool registry.

3. **Atomic LLM hot-swap with request buffering** (2026.8.1-beta.2): Buffer in-flight requests, swap the provider, replay. Particularly relevant given Lexicon's `llm/router.py` already routes across providers; adding a swap-with-drain step would let live sessions survive provider changes.

4. **Memory Core index repair on startup** (2026.7.1-1): The patch that fixed Memory Core startup when index conflicts exist surfaced a real reliability gap. Validating index integrity at init (and auto-healing before the first query) is a low-effort, high-stability improvement.

5. **Session checkpoint/branching** (2026.7.2-beta.7): Storing conversation checkpoints and branching from them enables both user-facing "rewind" UX and internal eval/testing patterns (branch from a fixed state, run N variants). Lexicon's episodic memory layer is the natural home.

## My Picks for Next Spike

**1. Gateway circuit-breaker** (`src/gateway/server.py`)  
One file, two additions: a consecutive-failure counter and a `repair_mode` boolean. Low risk, immediately observable via health checks. Patch 2026.7.1-1 confirms this is a real operational gap (Memory Core index conflicts caused similar loop behavior there).

**2. Memory Core index repair** (`src/engine/memory/manager.py` + `src/engine/memory/transcript_index.py`)  
The upstream patch existed because the bug was real. Lexicon's `transcript_index.py` runs on startup; adding an integrity check + rebuild step before the first query is a direct port of the same fix.
