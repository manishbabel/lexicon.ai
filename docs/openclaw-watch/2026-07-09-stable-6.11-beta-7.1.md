## What's Notable

**1. Event-driven cron (`on-exit` trigger) — beta**
Scheduling fires on a command exit rather than a clock tick. Opens reactive chaining: finish RSS fetch → immediately run summarizer, without polling. The `on-exit` kind is paired with clean session detachment so the scheduler doesn't block waiting.

**2. Memory re-ingestion protection — stable**
When source content is re-synced, user-curated notes survive. Only derived/generated content is overwritten. Critical for any agent that indexes external feeds into a vault where users also write annotations.

**3. Provider fallback chain — stable**
On provider error or rate-limit, the LLM router activates the next configured provider and resumes from the prompt checkpoint (not replaying tool results). The isolation between tool-call history and prompt-only state is the key design detail.

**4. QMD search timeout + cancel — stable**
Timeouts previously let background threads continue consuming resources. Now they propagate a cancellation signal. In long-running agents, this prevents gradual resource accumulation from piled-up timed-out searches.

**5. Gateway run-cache growth caps — beta**
Long-lived gateway sessions accumulate run artifacts unboundedly. Beta introduces explicit caps, evicting oldest entries. Pair this with the session detach pattern from `openclaw attach` to give sessions a clean truncation point.

## Spike Picks

**Spike 1 (now): Provider fallback chain** — `src/engine/llm/router.py`
The lowest-effort, highest-reliability win. Add an ordered `fallback_providers` config key; `LLMRouter` catches provider errors and rate-limit responses, then retries with the next entry. The non-obvious detail from OpenClaw: resume from the prompt checkpoint only, not replaying tool-call results — guards against double-execution of side-effectful tools.

**Spike 2 (next): Event-driven cron** — `src/cron/scheduler.py` + `src/cron/defaults.py`
Architecturally the most novel pattern in this cycle. Add a `trigger: on_exit` schedule kind with a `watch_tool` field; `scheduler.py` subscribes to tool-completion events from the engine and fires the cron job when the watched tool reports done. This eliminates polling-based chaining between Lexicon's agents and enables clean multi-agent pipelines.
