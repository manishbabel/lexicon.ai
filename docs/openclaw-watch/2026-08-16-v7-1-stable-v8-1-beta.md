## What's notable

### 1. Fail-closed secret egress binding (2026.8.1-beta.2)
Secrets are now bound to specific egress hosts in the shared store. Any substitution that cannot resolve a binding fails closed before the value reaches plaintext egress — CLI, Gateway RPC, and Control UI all enforce this. The pattern: secrets carry an allowed-host assertion at write time, and the read path verifies it before emission, not at call sites.

### 2. Fallback provider chaining during execution (2026.6.34)
Rather than failing a run on provider error, OpenClaw now retries through a declared provider chain with retained session writes. The session state is preserved across the failover so the next provider picks up where the previous one stalled. Stream-progress state is also carried across transitions.

### 3. Idempotent channel acknowledgments with burst bounds (2026.6.34)
Channel delivery (Discord gateway, but the pattern generalizes) was hardened by making acks idempotent and capping sustained burst traffic. A pending-work queue that survives recovery cycles ensures messages aren't re-delivered or dropped on reconnect. The pattern separates "delivery attempted" from "delivery confirmed" and adds a bounded retry budget.

### 4. Checkpoint-based session recovery (2026.7.1)
Sessions now write checkpoints before handoffs (compaction, provider switch, channel transition). Recovery reads the last clean checkpoint rather than replaying the full transcript. The gateway prevents infinite restart loops by tracking failure counts and offering a repair path instead of cycling indefinitely.

### 5. Rate-limiting on control-plane operations (2026.8.1-beta.2)
Admin/control operations are now subject to per-method rate buckets (30/min for interactive admin ops). This is applied at the Gateway layer, decoupled from application-level auth, and prevents runaway automation or abuse from overwhelming management surfaces.

## What we can use in Lexicon

Ranked by **value × inverse-effort** (highest first). All file paths verified to exist.

### 1. Fail-closed secret binding in config — HIGH value / LOW effort
**Pattern:** At secret write time, record the allowed egress host. At read time, assert host matches before returning plaintext.  
**File:** `src/shared/config.py`  
Currently config exposes values directly with no emission guard. Adding a `Secret` wrapper with a `host` assertion and a `get(host)` method that returns `None` on mismatch would replicate the pattern with minimal disruption.

### 2. Fallback provider chaining — HIGH value / MEDIUM effort
**Pattern:** Router tries providers in declared order; on stream failure, retains session writes and hands off to the next provider without resetting context.  
**File:** `src/engine/llm/router.py`  
The router exists but it's unclear if it has multi-provider fallback. Adding an ordered `fallback_chain` and a session-state checkpoint before each provider attempt would close this gap. Pairs with `src/engine/llm/provider.py` for the base interface.

### 3. Idempotent message acknowledgment in gateway session — MEDIUM value / MEDIUM effort
**Pattern:** Separate delivery-attempted from delivery-confirmed; make acks idempotent; cap retry burst.  
**File:** `src/gateway/session.py`  
Session handling could track a per-message delivery state enum (PENDING → ATTEMPTED → CONFIRMED) and deduplicate re-deliveries by message ID. The burst cap is a simple token-bucket in the session write path.

### 4. Rate-limiting on gateway admin routes — MEDIUM value / LOW effort
**Pattern:** Per-method token bucket at the Gateway layer, 30/min for control-plane operations.  
**File:** `src/gateway/server.py`  
The server handles routing but likely has no rate-limiter on admin/management endpoints. Adding a per-method `asyncio`-based token bucket middleware is low-effort and high-leverage for multi-tenant or exposed deployments.

### 5. Checkpoint writes before runtime handoffs — HIGH value / HIGH effort
**Pattern:** Write a recoverable checkpoint before compaction, provider switch, or channel transition. Recovery starts from the last clean checkpoint.  
**Files:** `src/engine/runtime.py`, `src/engine/memory/working.py`  
Working memory is in-process; adding a serialized checkpoint flush before `runtime.py` initiates a handoff would enable restart recovery. Episodic memory at `src/engine/memory/episodic.py` is a natural durable store for checkpoints.

## My picks for what to spike next

**Spike 1 — Fail-closed secret binding (`src/shared/config.py`)**  
Low effort, high security payoff, no architectural dependency. Ship in isolation. A `Secret(value, allowed_hosts)` namedtuple with a `get(requesting_host)` accessor that logs and returns `None` on mismatch is a one-afternoon change.

**Spike 2 — Fallback provider chaining (`src/engine/llm/router.py`)**  
Lexicon already has a multi-provider LLM layer (claude, openai, litellm providers all present). Wiring them into an ordered fallback chain with session-state preservation on failure would make the runtime significantly more resilient with medium effort.
