## What's notable

### 1. Gateway repair-path on repeated failure (2026.7.1)
Gateways that fail repeatedly now enter a stable repair path instead of restarting indefinitely. The pattern: detect N consecutive failures → pause → surface a repairable state rather than thrashing. Startup, restart, migration, and streaming failures each have explicit recovery states.

### 2. Durable subagent result delivery (2026.11.10-beta.3)
Finished subagent output is persisted independently of the parent session. If the Gateway restarts or the parent session turns over, completed child results are still delivered. Delivery failures are surfaced explicitly rather than silently dropped. Mid-task steering (new instructions reaching a busy subagent) is also supported.

### 3. Selective transcript indexing (2026.11.10-beta.3)
Execution wake output and unused tool lookups are excluded from session indexing. Compacting or opening long conversations uses less memory and main-thread time. This is a targeted exclusion-list approach rather than a full re-architecture.

### 4. Durable automations surviving restarts (2026.11.10-beta.3)
Scheduled work survives session edits, sharing changes, upgrades, and Gateway restarts. Cron replies and failure notices are deduplicated after recovered tool calls or silent replies — preventing the common double-fire pattern on restart.

### 5. Live config reload without Gateway restart (2026.11.10-beta.3)
Saved MCP server configuration changes apply immediately from the CLI without stopping the Gateway. First chats are accepted while model catalogs still load (non-blocking startup).

## What we can use in Lexicon

Ranked by value/effort. All file paths verified to exist under `src/`.

| 5 | **Subagent result durability** | Medium | High | `src/engine/orchestrator.py`, `src/engine/runner.py` |

### Detail

**1. Selective transcript indexing → `src/engine/memory/transcript_index.py`**
Exclude execution-wake turns and tool-lookup responses that go unused from the index. This directly reduces memory pressure in long Lexicon sessions without changing retrieval semantics. The change is additive: add a filter predicate to what gets indexed.

**2. Cron deduplication on restart → `src/cron/scheduler.py` + `src/cron/store.py`**
When Lexicon's cron scheduler recovers from a crash or restart, it can fire a job whose result was already delivered — producing duplicate channel posts. Add an idempotency key (job_id + fire_time) checked against `src/cron/store.py` before dispatching. Low-risk and self-contained.

**3. Gateway repair-path → `src/gateway/server.py` + `src/gateway/session.py`**
Replace the current restart-on-failure loop with a counted failure detector: after N failures, stop retrying and emit a repairable sentinel state that the caller can inspect. Prevents thundering-restart behaviour under sustained errors.

**4. Live config reload → `src/gateway/server.py` + `src/shared/config.py`**
Watch `src/shared/config.py` for filesystem changes (or add a signal handler) and reload MCP/provider config without tearing down active sessions. Medium effort because session state must remain consistent across the reload boundary.

**5. Subagent result durability → `src/engine/orchestrator.py` + `src/engine/runner.py`**
Persist completed subagent results to `src/cron/store.py` or a dedicated queue before acknowledging back to the parent. High effort: requires a durable handoff protocol between `src/engine/orchestrator.py` (parent) and `src/engine/runner.py` (child), plus replay on restart.

## Picks for next spike

**Top pick: Selective transcript indexing** (`src/engine/memory/transcript_index.py`)
Self-contained, additive, directly reduces memory growth in long Lexicon sessions. Proof-of-concept: add a `should_index(turn)` predicate that skips `role == "tool"` turns where the tool result was never referenced by a subsequent assistant turn. Low blast radius.

**Second pick: Cron deduplication** (`src/cron/scheduler.py` + `src/cron/store.py`)
Any Lexicon cron job that posts to a channel can double-fire after a process restart. Adding an idempotency key is a small, verifiable change with real correctness value.
