## What Shipped

### Stable line: 2026.9.9 (Oct 8) — and the 2026.9.x arc

Headline changes since 2026.5.27:

- **Prepared runtime reuse for background work** (9.9): Skill Workshop reviews and rooted cron jobs now reuse the already-prepared runtime instead of rebuilding it. Background work no longer stalls the Gateway.
- **LLM catalog sync** (9.9): Managed Codex app-server updated to 0.160.0; native sessions can discover GPT-6.1 Sol. Synchronized protocol + model metadata.
- **Stale cron cleanup & queued cancellation** (9.9): A stale cron entry no longer aborts the next scheduled run; queued cancellation no longer stalls active turns.
- **WAL ownership inspection** (9.9): Live WAL ownership checked against live state rather than unstable full-database copies during admission. Session creation bound to physical SQLite store identity.
- **2026.8.35 (gateway-only extended-stable)**: Security and ownership hardening backport. Also included GPT-6.1 Sol, safer update/recovery, more reliable agent completion.

Intermediate releases (2026.6–2026.9.8) were primarily dep bumps, messenger-channel fixes (iMessage, Discord, Telegram), and Windows/sandbox stability work. No architecture patterns worth porting were identified in those.

### Beta line: 2026.10.1-beta.1 / beta.2 (Oct 5–8) — 2,403 PRs

This is the largest release in the tracked window. Beta.2 is a 40-commit hotfix on top of beta.1 (update/Doctor recovery, auth checks, no new capabilities).

Key additions in beta.1:

- **Code Mode persistence**: `store`/`load` API persists session-scoped values across cells, replies, and Gateway restarts. Limits: 256 KiB/value, 1 MiB/session.
- **Off-machine backups**: External disk, NAS, Cloudflare R2 targets; client-side encryption by default; explicit init required. Health and results surfaced in UI.
- **Transcript import**: Import readable transcripts from Claude Code, Codex, OpenCode, Pi, OpenClaw into sessions via CLI or UI. Incremental reimport supported.
- **Installed-skill search**: Searches names, descriptions, *and instruction content* so skills stay discoverable within prompt budgets.
- **Automations — condition scripts**: Cron automations can run a condition script to skip quiet checks without a model run. Scripts may call explicitly permitted MCP servers. Cross-job history and inventory search added.
- **Lifecycle writes off main thread**: Session persistence now awaited through a writer; lifecycle workers drain on CLI exit. Synchronous adapters deprecated with warnings.
- **Memory plugin flush ownership**: Plugins can own their pre-compaction flush and use their own persistence tools. Default Memory Core behavior unchanged.
- **Scoped MCP tool grants**: An MCP App can request ephemeral permission for a specific tool while its view is open (10-min TTL, view-scoped, not a persistent allowlist).
- **`openclaw claws migrate`**: Moves existing agents to local Claws, preserving workspace and sessions (opt-in).
- **Breaking**: Third-party plugins importing retired compatibility facades or whole-session-store helpers must migrate. Bundled plugins already migrated.

## What's Notable

1. **Background runtime reuse (9.9)**: Builds the runtime once and shares it across cron and skill-review work instead of constructing a fresh runtime per job. Directly relevant to how Lexicon's scheduler cold-starts for each cron tick.

2. **Automation condition scripts (beta.1)**: A lightweight pre-check gate on the cron loop — run a cheap script first, skip the expensive model call if nothing changed. Enables silent heartbeat passes. The allowed-MCP-servers constraint shows a disciplined capability model for scheduled jobs.

3. **Installed-skill search by instruction content (beta.1)**: Full-text search over skill instructions, not just names/descriptions. Solves the prompt-budget vs. discoverability tradeoff without expanding the context window.

4. **Lifecycle off-thread + drain-on-exit (beta.1)**: All persistence writes are async and drained on shutdown. Prevents data loss on abrupt exit and keeps the main agent loop from blocking on I/O.

5. **Scoped ephemeral MCP grants (beta.1)**: A time-and-view-bounded capability grant pattern for tool use, rather than a static allowlist. Reduces the blast radius of a misbehaving tool integration.

## What We Can Use in Lexicon

Ranked by value/effort (high value first):

### 1. Automation condition scripts — `src/cron/scheduler.py` + `src/cron/defaults.py`
**Value: High / Effort: Low**  
Add an optional `condition` callable to each cron job spec. If it returns falsy, the scheduler skips the model run for that tick and logs a `noop`. Keeps the heartbeat lightweight on quiet ticks. `src/cron/defaults.py` holds job specs; `src/cron/scheduler.py` is where the run loop fires jobs.

### 2. Prepared runtime reuse for cron — `src/engine/runtime.py` + `src/cron/scheduler.py`
**Value: High / Effort: Medium**  
The scheduler currently constructs runtime context per job. Caching and reusing the prepared runtime (models loaded, hooks resolved) across cron ticks avoids repeated initialization cost, matching OpenClaw 9.9's approach. The runtime is initialized in `src/engine/runtime.py`; the scheduler calls it in `src/cron/scheduler.py`.

### 3. Skill instruction-content search — `src/engine/skills.py` + `src/engine/tools/registry.py`
**Value: High / Effort: Medium**  
Index skill instruction text alongside names/descriptions so the dispatcher can find a skill by capability keyword without expanding the system prompt. `src/engine/skills.py` manages skill loading; `src/engine/tools/registry.py` is the lookup layer.

### 4. Async lifecycle writes with drain-on-exit — `src/engine/runner.py` + `src/engine/queue.py`
**Value: Medium / Effort: Medium**  
Move session state persistence off the main agent loop into an async writer; drain the queue on `runner.py` shutdown. Prevents blocking the orchestrator on I/O and guards against data loss on SIGTERM. `src/engine/queue.py` already has a queue abstraction; the drain hook belongs in `src/engine/runner.py`.

### 5. Transcript import into memory — `src/engine/memory/transcript_index.py`
**Value: Medium / Effort: High**  
Accept a transcript from an external session (e.g., a Claude Code session) and insert it into the memory index, enabling retrieval across agent lifetimes. `src/engine/memory/transcript_index.py` already manages transcript-level indexing; the import path would add an ingest entrypoint.

## My Picks — What to Spike Next

**Spike 1: Condition scripts on cron jobs** (`src/cron/scheduler.py`)  
Pure logic addition, no external deps, directly reduces wasted model calls on quiet ticks. Target: a `condition` callable field in the job spec, evaluated before `run_job`. One file, one day.

**Spike 2: Prepared runtime reuse** (`src/engine/runtime.py`, `src/cron/scheduler.py`)  
Once the condition-script spike is in, cache the runtime at scheduler init and reuse it per tick. The two spikes compose cleanly — condition scripts run fast, full model runs use the warm runtime.
