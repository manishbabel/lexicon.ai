## What's Notable

### 1. Swarm Parallelization (2026.8.1)
Fan out bounded parallel subagents, await structured results, follow progress from a parent session. Child-task completion is routed back to the requesting session rather than lost in an undelivered-notice queue. This is first-class multi-agent composition inside a single runtime, with a Labs opt-in gate.

### 2. Plugin Hot-Reload (2026.9.5)
Plugins install without restarting the Gateway. Official verified plugins also skip a redundant approval step before sign-in. The mechanism separates plugin lifecycle management from process lifecycle — plugins are loaded/unloaded as live modules, not startup state.

### 3. Live Model Discovery (2026.8.1)
Providers expose their available models at runtime rather than relying on a bundled catalog snapshot. Coupled with provider package separation (BytePlus, ComfyUI, Mistral, etc. as discrete installable packages), this decouples the core from provider churn and enables adding new providers without updating the main process.

### 4. Provider-Managed Context Compaction (2026.8.1)
Server-side compaction for Anthropic and xAI as a beta opt-in, while preserving the full local transcript. This separates the "what to send to the model" problem from "what to keep in the local store."

### 5. Memory Ownership & Source Tracking (2026.8.1)
Sessions that contributed to derived memories are now tracked and inspectable. Users can exclude specific contributing sessions, and identifiable derived memories can be removed while preserving the original source transcripts. Selective attribution at the memory-graph level.

## Picks for Next Spike

**Spike A — Plugin hot-reload in `src/engine/hooks/loader.py`**
The current `loader.py` almost certainly loads hooks at process start and holds them until restart. OpenClaw's pattern is: detect module change → unload old code object → re-import in place → re-register in `hooks/registry.py`. Benefit to Lexicon: skill iteration without gateway bounce, directly unblocks the skills-authoring loop. Scope is one file plus a small addition to `skills.py`.

**Spike B — Live model discovery in `src/engine/llm/router.py`**
`router.py` likely routes by a static list of provider-registered models. Adding a `discover()` method to the `Provider` base in `provider.py` (with a fallback to the static catalog for providers that don't implement it) is low-risk and directly future-proofs the router against new model additions without a deploy.
