## What's Notable

1. **State-change-gated scheduling** — Firing jobs only when a relevant state hash changes eliminates the most common wasted agent run: a watch job that polls, finds nothing new, and still consumes a full agent turn. This is a first-class scheduler concept in OpenClaw now, not a workaround.

2. **Consecutive-error circuit breaker** — Crash loop prevention goes hand in hand with already-tracked `consecutive_errors` state. The pattern: check the error counter before firing, skip (or disable) after a threshold, emit a hook so operators are notified. OpenClaw's implementation produces a "stable repair path" rather than a silent disable.

3. **Crash-recoverable cron state via SQLite** — JSON file writes are not atomic; a crash mid-write corrupts the file. The quarantine+snapshot pattern (write to quarantine store, promote on clean startup) protects job state without requiring a full SQLite migration.

4. **LLM provider fallback chains** — The extended-stable backport of provider resilience confirms this is considered production-critical. The pattern is: try primary provider, catch transient errors, retry down a declared fallback list, emit a warning metric.

5. **Secret egress host binding** — Declaring outbound host allowlists at the tool/channel layer (not just in network policy) gives defense-in-depth: a compromised tool can't exfiltrate to an undeclared host even if the OS firewall is misconfigured.

## My Picks for What to Spike Next

**Spike #1 — Circuit breaker in `src/cron/scheduler.py`** ← start here

`CronJobState.consecutive_errors` is already incremented on failure (scheduler.py:222) and persisted to `jobs.json`. The only missing piece is a check at the top of `_execute_job()`:

```python
MAX_CONSECUTIVE_ERRORS = 5  # or configurable per job

if job.state.consecutive_errors >= MAX_CONSECUTIVE_ERRORS:
    logger.warning(f"Job {job_id} circuit-breaker open ({job.state.consecutive_errors} errors), skipping")
    await trigger_hook("cron:circuit_open", {"job_id": job_id, "errors": job.state.consecutive_errors})
    return
```

This prevents runaway failing jobs from burning agent turns indefinitely. Cost: ~10 lines. Risk: near-zero (purely additive guard). The hook gives operators visibility.

**Spike #2 — Atomic writes in `src/cron/store.py`**

Replace `self._path.write_text(...)` with:

```python
import os, tempfile
tmp = self._path.with_suffix(".tmp")
tmp.write_text(json.dumps(data, indent=2, default=str) + "\n")
os.replace(tmp, self._path)
```

`os.replace` is atomic on POSIX. Cost: 3 lines. Prevents the silent corruption scenario where a crash during `write_text` leaves a partial JSON file that breaks `load()` on next boot.

**Spike #3 — Provider fallback in `src/engine/llm/router.py`** (worth a separate PR)

Add `fallback_llm_providers: list[str]` to `SharedConfig`, then wrap `_get_provider()` in a try/except that walks the fallback list before raising. This is the highest-production-value pick but needs a settings migration plan.
