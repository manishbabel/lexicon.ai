## What's Notable

### 1. Gateway crash-loop recovery with control-plane-safe mode (2026.7.1)
Repeatedly failing gateways now persist their boot outcome, enter a *control-plane-safe* mode after N unclean starts (holding transport and provider activation), and exit with `EX_CONFIG` for fatal configuration errors. This replaces an infinite restart loop with a deterministic repair path. Pattern: boot-outcome file + escalating backoff state machine + well-defined exit codes.

### 2. Event-driven cron — "wake only when something changes" (2026.7.1)
Scheduled work can be configured to fire only when a monitored condition changes (e.g. a file checksum, a feed hash, a queue depth) rather than on a pure time interval. This eliminates no-op fires for polling jobs. Pattern: a lightweight pre-check predicate attached to job definitions; the scheduler short-circuits execution if the predicate returns unchanged.

### 3. Active-goal pinning across memory compaction (2026.7.1)
Active goals now survive transcript compaction, queue restarts, and session interruptions by being tagged as `pinned` in working memory. Standard eviction does not touch pinned entries. Memory manager promotes pinned entries back into context after compaction. Pattern: role/tag field on memory entries; compactor checks tag before evicting.

### 4. Skill Workshop — plugin governance + SQLite-backed plugin state (2026.6.1)
Skills and plugins now have formal contracts (declared inputs/outputs/permissions). Installed-plugin state (enabled/disabled snapshots, support-file approvals) is persisted to SQLite so it survives reloads. Skill Workshop adds a proposals dashboard and revision flow separate from the runtime registry. Pattern: contract schema per plugin, persistent state store decoupled from in-memory registry.

### 5. Plugin externalization as first-class packages (2026.6.1)
The Tokenjuice LLM-routing plugin and Copilot agent runtime were extracted from core into `@openclaw/tokenjuice` and `@openclaw/copilot` — separately versioned, published to npm/ClawHub, with explicit package boundary contracts. Pattern: thin adapter + contract interface in core; implementation ships as an independently installable package.

## What We Can Use in Lexicon

Ranked by value/effort. All file paths verified against the current `src/` tree.

### ★★★ High value / Low effort — Gateway crash-loop recovery
**What:** Add a boot-outcome file and a consecutive-failure counter to `src/gateway/server.py`. After N failures in the `lifespan()` startup block, log `EX_CONFIG`-equivalent and raise a non-retriable exception rather than letting the process restart indefinitely into a broken state.

**Files:** `src/gateway/server.py` (lines 60–140, the `lifespan()` async context manager)

**Sketch:** Track startup attempts in a sidecar file (e.g. `.gateway_boot_state.json` under the data dir). On each entry to `lifespan()`, increment the counter; clear it on clean shutdown. If counter exceeds threshold, log at `CRITICAL` and `sys.exit(78)` (EX_CONFIG) so the supervisor doesn't retry.

**Effort:** ~30 lines in `server.py` + constants in `src/shared/constants.py`.

---

### ★★★ High value / Medium effort — Event-driven cron predicates
**What:** Today `CronScheduler._execute_job()` always runs when the trigger fires (`src/cron/scheduler.py:177`). Add an optional `condition` field to `CronJob` — a callable or a stored hash — that short-circuits execution if nothing changed.

**Files:** `src/cron/scheduler.py` (lines 177–246), `src/cron/store.py` (CronJob model)

**Sketch:** Add `condition_key: str | None` and `last_condition_hash: str | None` to `CronJob`. Before `_execute_agent()`, compute a hash of the watched resource (file, URL, queue depth) and compare to `last_condition_hash`. Skip and persist new hash if unchanged. The per-job system handler approach already exists; this adds a pre-check hook.

**Effort:** ~50 lines across scheduler + store; no APScheduler changes needed.

---

### ★★ Medium value / Low effort — Pinned entries in WorkingMemory
**What:** `WorkingMemoryEntry` has a `metadata` dict but no explicit `pinned` flag (`src/engine/memory/working.py:27`). Goals and steering instructions currently evict like any other entry when the deque is full. Add `pinned: bool = False` and skip pinned entries during eviction.

**Files:** `src/engine/memory/working.py` (lines 27–76), `src/engine/context/compactor.py`

**Sketch:** `WorkingMemoryEntry` gains `pinned: bool = False`. In `WorkingMemory.add()`, before evicting the oldest entry, skip any pinned ones (walk forward until a non-pinned entry is found or the capacity is not exceeded). The compactor at `src/engine/context/compactor.py` should re-inject pinned entries after compaction.

**Effort:** ~20 lines in `working.py`; coordinate with `compactor.py`.

---

### ★★ Medium value / High effort — Plugin contracts + persistent state
**What:** `src/engine/tools/registry.py` and `src/engine/skills.py` hold tools/skills in-memory with no formal contract schema and no persistence of enabled/disabled state across restarts. Adding a contract layer (declared tool name, description, permissions, required config) and a SQLite-backed enabled-state store would make the registry observable and survivable.

**Files:** `src/engine/tools/registry.py`, `src/engine/skills.py`, `src/engine/tools/setup.py`

**Sketch:** Define a `ToolContract` dataclass (name, description, permissions, required_env). `setup_tools()` in `src/engine/tools/setup.py` validates contracts at startup. A small SQLite table (or JSON sidecar) persists `{tool_name: enabled}` across restarts.

**Effort:** 2–3 days; requires schema design and migration consideration.

---

### ★ Lower value / Low effort — Session metadata (title + unread state)
**What:** `src/gateway/session.py` tracks sessions but has no title, unread-message count, or lifecycle flags (archived/forked). Adding these to the session model enables a richer session-list UI and resume flows.

**Files:** `src/gateway/session.py`

**Sketch:** Add `title: str | None`, `unread: int`, `archived: bool` to the session model. Title can be generated by the LLM router on first substantive turn (OpenClaw uses a utility-model call). `unread` increments on agent output, resets on client ack.

**Effort:** ~40 lines; mostly data model + one LLM call.

## My Picks — What to Spike Next

1. **Gateway crash-loop recovery** (`src/gateway/server.py`) — highest signal-to-effort ratio. The current lifespan doesn't guard against restart loops at all. A 30-line addition closes a real operational gap. Spike: add boot-state tracking and test with a deliberate misconfiguration.

2. **Event-driven cron predicates** (`src/cron/scheduler.py`) — the OpenClaw cron "wake on change" pattern directly maps to Lexicon's existing `CronJob` + `CronScheduler` shape. Would eliminate empty blog-watcher and RSS runs. Spike: add a `condition_hash` field to `CronJob` and wire a file-hash check into the existing `_execute_job()` path.
