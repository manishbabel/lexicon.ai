## What's Notable

### 1. PostgreSQL-backed state plane (beta: 2026.11.5-beta.1)
OpenClaw replaced its JSONL/flat-file memory and automation stores with a PostgreSQL data plane, adding migration tooling and compatibility for existing deployments. Memory maintenance, cleanup, and recovery now run as database operations rather than file scans. The iMessage channel in 2026.11.1 already requires Postgres-backed cursor state.

### 2. Task-type model routing via ClawRouter (beta: 2026.11.5-beta.1)
Routing moved from a single persona→provider map to a two-axis scheme: persona axis (which agent) × task-type axis ("decision" model, "media" model, general chat). ClawRouter dispatches the right model per turn type. Bedrock Mantle in 2026.11.1 similarly routes by API-capability (numbered GPT → Responses API, GPT-OSS → Chat Completions, Claude → Anthropic Messages).

### 3. Scheduler startup guard against stale running state (stable: 2026.11.1 + beta: 2026.10.10-beta.5)
OpenClaw fixed a class of bugs where interrupted long-running cron jobs left a "running" sentinel in persisted state, causing the scheduler to skip or block on restart. The fix: on startup, any job in state `running` is reset to `unknown`/`interrupted` before the scheduler begins accepting new triggers. Cancelled cron runs also now stop their reply hooks.

### 4. Compaction preserving the active human request (stable: 2026.11.1)
Context compaction was updated to hold the most-recent human turn out of the compactable window, so repeated compaction passes don't discard the question currently being answered. Queue-overflow summaries also now keep sender and conversation context.

### 5. Provider rate-limit backoff fix (stable: 2026.11.1)
Local exponential backoff no longer accumulates across hours — a cap was introduced so a burst of 429s doesn't lock out a provider until the next restart. API key rotation (Google) is applied after a rate-limit hit rather than after all keys are exhausted.

## What We Can Use in Lexicon

Ranked by value/effort. Each entry maps to a real file that exists under `src/`.

### A — Scheduler startup guard  
**Value: HIGH / Effort: LOW**

`src/cron/scheduler.py` loads job state from `~/.lexicon/cron/jobs.json` via `src/cron/store.py`. Any job whose `last_status` is `"running"` at startup represents a job that was interrupted mid-flight. The scheduler currently doesn't reset these — it will re-run the job on its next trigger, but the stale state can cause misleading error counts and, in future, could block catch-up logic.

**Pattern to port:** in `CronScheduler.start()` (line 85), after loading stored jobs, iterate and reset any `job.state.last_status == "running"` to `"interrupted"` before registering triggers. This is a 3-line addition in `src/cron/scheduler.py`.

### B — Task-type routing dimension in PersonaLLMRouter  
**Value: MEDIUM / Effort: LOW**

`src/engine/llm/router.py` routes by persona only (`_provider_for_persona`, `_model_for_persona`). OpenClaw's ClawRouter adds a second routing axis: task type (`"decision"`, `"fast"`, `"reasoning"`, `"multimodal"`). This would let Lexicon use a cheap/fast model for cron summaries and a more capable model for real-time agent turns, without splitting into separate personas.

**Pattern to port:** add an optional `task_type: str | None` parameter to `PersonaLLMRouter.resolve()` and a `_model_for_task_type()` lookup that checks settings before falling back to persona defaults.

### C — Compaction preserving the active human turn  
**Value: MEDIUM / Effort: LOW**

`src/engine/context/compactor.py` protects the last `PROTECTED_TAIL = 6` messages from compaction (line 29). OpenClaw's fix ensures the most-recent *human* message is always in the protected tail, not just the most-recent N messages (which could be assistant turns after a tool call). 

**Pattern to port:** in the compactor's protected-tail logic, scan backwards from the end and ensure at least one `role == "user"` message is included in the tail window. Single-file change in `src/engine/context/compactor.py`.

### D — Provider rate-limit backoff cap  
**Value: MEDIUM / Effort: MEDIUM**

`src/engine/llm/provider.py` defines the `LLMProvider` interface. None of the concrete providers (`src/engine/llm/openai_provider.py`, `src/engine/llm/claude_provider.py`, `src/engine/llm/litellm_provider.py`) currently cap exponential backoff. Under sustained 429s the effective retry delay can grow to hours.

**Pattern to port:** add a `MAX_RETRY_DELAY_SECONDS` cap (e.g. 60s) in each provider's retry loop, and optionally cycle through API keys before giving up (if multi-key support is added to `src/shared/config.py`).

### E — PostgreSQL memory backend  
**Value: HIGH / Effort: HIGH**

`src/engine/memory/short_term.py` and `src/engine/memory/episodic.py` write to JSONL files. These are fast to implement and zero-dependency, but they don't survive container restarts across deployments and can't be queried by other processes. OpenClaw's migration from flat files to Postgres (with a migration tool) is the right long-term direction for Lexicon if it moves toward multi-instance or cloud deployments.

**Pattern to port:** implement a `ShortTermMemoryBackend` / `EpisodicMemoryBackend` protocol in `src/engine/memory/manager.py`, then add a Postgres implementation behind a config flag. JSONL stays the default.
