## What's notable

### 1. Grounded Dreaming — background memory consolidation
`2026.8.1`  
A background task promotes provenance-tracked material into long-term memory and writes a Dream Diary. Diary entries are written on a delayed timer after startup. Overlapping reset cycles are serialized to prevent memory file overwrites. The consolidation loop also resurfaces active-memory recall outcomes to the model.

### 2. Cron resilience: skip-missed-jobs + malformed-row quarantine
`2026.9.1`  
Two independent changes: `cron.skipMissedJobs` suppresses burst recovery when the scheduler restarts late (prevents task floods after downtime); malformed legacy cron rows are quarantined rather than blocking the entire cron subsystem startup. ISO dates in cron specs now respect timezone offsets.

### 3. Hooks token isolation from child environments
`2026.10.10-beta.4` / backported to `2026.9.35`  
Gateway hooks token is no longer passed into child agent environments, preventing a sandboxed subagent from using it to call back to the Gateway. POSIX exec allowlists also no longer auto-trust `test -v` / `[ -v` checks.

### 4. Utility/fallback model routing
`2026.8.1` / `2026.10.8`  
A provider's smallest eligible model handles non-primary tasks (titles, progress text). For long native conversations, an eligible fallback model handles summarization when the primary model can't fit the context. Model selection scope can be session, agent, or shared default.

### 5. SSRF `blockedHostnames` policy
`2026.9.1`  
A new `blockedHostnames` config key in the SSRF policy explicitly denies browser, web-fetch, and webhook requests to listed hostnames, complementing the existing allowlist. This is a defense-in-depth measure against SSRF through tool use.

## What we can use in Lexicon

Ranked by value/effort. All file paths verified against the current `src/` tree.

| # | Pattern | Value | Effort | Lexicon files |
|---|---|---|---|---|

**Details:**

**#1 — Cron skip-missed + quarantine** (`src/cron/scheduler.py`, `src/cron/store.py`)  
`scheduler.py`: on startup, compare each job's `next_run` against `now()`; if overdue and `skipMissedJobs` is set, advance to next window instead of firing. `store.py`: wrap the cron row deserialization in a try/except; move unparseable rows to a `quarantine` table with an error note and continue loading.

**#2 — Hooks token isolation** (`src/engine/hooks/registry.py`, `src/engine/runtime.py`)  
In `hooks/registry.py` (or wherever env is assembled before spawning a hook subprocess), strip any `LEXICON_GATEWAY_TOKEN`, `LEXICON_SESSION_TOKEN`, or equivalent credential keys before exec. Child agent envs should inherit only non-sensitive context.

**#3 — SSRF blockedHostnames** (`src/engine/tools/web_search.py`, `src/engine/tools/rss_fetch.py`, `src/shared/config.py`)  
Add `ssrf.blocked_hostnames: []` to config schema. In both tool files, resolve the target hostname before fetching and reject if it matches the blocklist. Complements any allowlist already in place.

**#4 — Background memory consolidation** (`src/engine/memory/episodic.py`, `src/engine/memory/manager.py`)  
`episodic.py` already stores per-session memories; add a consolidation pass that runs on a timer (e.g. via `src/engine/heartbeat.py` if it exists, else `src/cron/scheduler.py`) to promote high-signal episodic entries into `working.py`/`manager.py` long-term store with a provenance tag. Start simple: a nightly digest written to a log file before building a full Dream Diary.

**#5 — Utility model routing** (`src/engine/llm/router.py`)  
`router.py` already handles provider selection; add a `utility_model` config key per provider. Route context-compaction calls (`src/engine/context/compactor.py`) and title-generation to the utility model. Prevents burning main-model tokens on housekeeping.

## Spike picks

1. **#1 Cron resilience** — highest reliability return for the least code. A startup burst after downtime is a real operational hazard.
2. **#2 Hooks token isolation** — one env-filter pass in `hooks/registry.py` before exec. Straightforward security hardening.
3. **#3 SSRF blockedHostnames** — three-file change, adds a meaningful defense layer for `web_search` and `rss_fetch` tools.
