## What's Notable

### 1. Background Memory Dreaming (2026.8.1)
OpenClaw introduced an async background process that consolidates episodic memories into long-term storage, tagging each promoted item with provenance (source transcript). The `openclaw memory forget` command removes derived memory while keeping source transcripts intact — a clean separation of raw observations from synthesized knowledge. Self-learning is on by default; an `approvalPolicy: "pending"` gate is available.

**Why it matters:** Lexicon's memory pipeline is currently linear and synchronous. A background consolidator with provenance tags would let the engine accumulate richer long-term knowledge without blocking the hot path.

### 2. Change-Triggered Scheduling (2026.7.1)
Scheduled jobs can now declare a wake condition: "fire only when relevant state changes" rather than on a pure time tick. This prevents spurious re-runs on empty polls and shifts scheduling from push-on-clock to push-on-signal.

**Why it matters:** Lexicon cron jobs (e.g. blog-watcher, OpenClaw-watch itself) currently run on fixed intervals regardless of whether there is new data. A change-trigger predicate would reduce noise and wasted LLM calls.

### 3. Concurrent Memory Write Safety (2026.10.8)
Concurrent session-memory captures were silently overwriting each other. The fix serialises captures (or uses conditional writes) so no observation is lost under parallel agent activity.

**Why it matters:** Lexicon's `src/engine/memory/manager.py` does not currently guard against parallel writes from multiple cron jobs or concurrent sessions. This is a latent data-loss bug under load.

### 4. Provider-Side Context Compaction (2026.8.1)
Instead of compacting context client-side before sending to the LLM, OpenClaw delegates compaction to the provider (Anthropic extended thinking, xAI) when the provider supports it. The client sends the full context and lets the provider decide what to trim.

**Why it matters:** Lexicon's `src/engine/context/compactor.py` does client-side pruning before every Claude call. Offloading to Anthropic's extended-context model would reduce heuristic errors and simplify the compactor logic. Maps directly to `src/engine/llm/claude_provider.py`.

### 5. Interrupt / Cancellation Propagation (2026.11.8)
Bulk operations (skill updates, channel shutdowns, session imports) now stop promptly on cancellation rather than running to completion. Interrupted progress commands no longer emit late success messages that confuse callers.

**Why it matters:** Lexicon's `src/engine/runner.py` and `src/engine/orchestrator.py` have no structured cancellation token. Long-running tool chains (e.g. `paper_fetch`, `rss_fetch` batches) can't be interrupted cleanly today.

## What We Can Use in Lexicon

Ranked by value/effort ratio (highest first):

### A. Concurrent memory write guard — HIGH value / LOW effort
**Files:** `src/engine/memory/manager.py`

Add a per-session asyncio lock (or SQLite `BEGIN IMMEDIATE`) around episodic writes. Prevents silent overwrites when multiple cron jobs overlap. This is a ~10-line fix with no API surface changes.

### B. Change-trigger predicate on cron jobs — HIGH value / LOW effort
**Files:** `src/cron/scheduler.py`, `src/cron/store.py`

Add an optional `change_trigger: Callable[[], bool]` field to the job spec. The scheduler checks it before firing and skips the run (updating `last_checked` only) when it returns false. The blog-watcher and OpenClaw-watch jobs are immediate candidates.

### C. Provider-side compaction for Claude — HIGH value / MEDIUM effort
**Files:** `src/engine/context/compactor.py`, `src/engine/llm/claude_provider.py`

When `claude_provider` detects a Claude 3.7+ model that supports extended context, skip client-side pruning and pass the full prompt. Fall back to `compactor.py` for other providers. Reduces heuristic token-trimming errors on long research sessions.

### D. Background memory consolidation loop — MEDIUM value / HIGH effort
**Files:** `src/engine/memory/manager.py`, `src/engine/memory/episodic.py`

Add an async background task (started at engine init) that periodically promotes high-frequency episodic items into `src/engine/memory/episodic.py`'s long-term store, writing provenance metadata. Gate promotion behind a threshold (e.g. seen ≥3 times in 7 days).

### E. Structured cancellation tokens — MEDIUM value / HIGH effort
**Files:** `src/engine/runner.py`, `src/engine/orchestrator.py`

Thread an `asyncio.Event` cancel token through `runner.py`'s tool-call loop and `orchestrator.py`'s step iterator. Tools like `paper_fetch` and `rss_fetch` check the token between items and raise `CancelledError` cleanly.
