## What's Notable (patterns, not features)

### 1. Non-blocking history reads via off-loop I/O
History retrieval and compaction are moved off the main request-handling loop. The gateway remains responsive under large-context turns. This is an architectural discipline: **I/O that doesn't need to be synchronous with a reply should not be**.

### 2. Structured sub-agent results + live progress as a default
Swarm mode shipping on by default normalises multi-agent use. The pattern: sub-agents return typed, structured results (not raw text); the orchestrator collects and merges them; live progress is a streaming side-channel, not the main output.

### 3. Scoped session visibility for tools
A three-tier visibility model (`all` / `agent` / `self`) on session-inspecting tools gives operators explicit control over cross-agent data access. Narrowing the default prevents unintended session bleed between agents in multi-tenant or multi-skill setups.

### 4. Async-first LLM provider calls
Provider adapters run tool calls asynchronously, not in a blocking coroutine. Results can be steered mid-flight (cancellation / steering over a persistent connection). Signals a move toward stateful provider sessions rather than stateless request/response.

### 5. Failure-alert policy persistence through job mutations
Cron jobs that are edited or cloned carry their alert policies forward. The lesson: scheduling metadata (alert routes, retry budgets, notification targets) should be owned by the job record, not derived at fire time.

## What We Can Use in Lexicon

Ranked by (value × feasibility). All file paths verified against `src/`.

### P1 — Non-blocking context compaction / history reads
**Effort:** low-medium | **Value:** high

`src/engine/context/compactor.py` and `src/engine/memory/transcript_index.py` run synchronously inside the request path today. Move the compaction and index-search calls to `asyncio.create_task` / a background executor so the gateway loop stays free.

Relevant files:
- `src/engine/context/compactor.py`
- `src/engine/memory/transcript_index.py`
- `src/gateway/session.py` (caller site)

### P2 — Async LLM tool-call execution in provider adapters
**Effort:** medium | **Value:** high

`src/engine/llm/openai_provider.py` (and `litellm_provider.py`) dispatch tool calls synchronously. Restructure to `async`-native dispatch so multiple tool calls in a single turn can run concurrently.

Relevant files:
- `src/engine/llm/openai_provider.py`
- `src/engine/llm/litellm_provider.py`
- `src/engine/llm/router.py` (result fan-in)

### P3 — Per-turn settings scoping in the runner
**Effort:** low | **Value:** medium

`src/engine/runner.py` doesn't currently guarantee that inline settings (verbosity, tracing flags) survive model fallbacks. Add a turn-scoped settings context that is passed explicitly through `src/engine/runtime.py` and restored on model switch.

Relevant files:
- `src/engine/runner.py`
- `src/engine/runtime.py`

### P4 — Cross-agent session visibility on route_to_agent
**Effort:** low | **Value:** medium

`src/engine/tools/route_to_agent.py` passes sessions without a visibility gate. Add a `session_visibility` field (`all` / `agent` / `self`) to the tool's config block, checked in `src/engine/registry.py` before routing.

Relevant files:
- `src/engine/tools/route_to_agent.py`
- `src/engine/registry.py`

### P5 — Failure-alert policy persistence in cron store
**Effort:** low | **Value:** medium

`src/cron/store.py` doesn't copy alert/notification config when a job is cloned. Add alert policy to the job schema in `src/cron/store.py` and carry it through clone/edit operations in `src/cron/scheduler.py`.

Relevant files:
- `src/cron/store.py`
- `src/cron/scheduler.py`

### P6 — Memory disk-usage monitoring
**Effort:** low | **Value:** medium

`src/engine/memory/manager.py` has no usage telemetry. Add WAL-size, embedding-cache size, and episodic-store row count as metrics; surface them in `src/shared/logger.py` structured output for ops visibility.
