## What's notable

### 1. Permission-gated scheduling loops (2026.8.1)
Owner-only `/loop` with fixed-interval or self-paced modes. Automations are scoped to their originating conversation. Heartbeat polls route to owner DM; unroutable polls are skipped rather than broadcast. This solves runaway cron bleed across sessions.

### 2. Channel message integrity on retries (2026.7.35 / 2026.9.5)
Queued, imported, streamed, and tool-result messages are preserved across retries, hooks, recovery, and channel lifecycle transitions. UTF-16-safe truncation. Channels (Discord, Slack, Telegram, Matrix, etc.) no longer lose or corrupt messages on partial failure.

### 3. Bounded memory consolidation with provenance (2026.8.1)
Model-backed background memory consolidation with explicit provenance qualification — stored memories are labelled by source context. Pairs with durable transcript branching: fork/rewind from any persisted user message, preserving earlier paths.

### 4. Automatic skill discovery (2026.8.1)
Scanner-approved capture of strong reusable lessons from sessions. Workshop review flow for manual scanning. External skill references pinned by commit through trusted registries. Skills self-register after approval rather than requiring manual authoring.

### 5. CPU-scaled concurrency (2026.8.1)
Default agent parallelism derived from available CPU cores with 8–16 bounds. Removes the "pick a number" hardcode for sub-agent fan-out and avoids over-scheduling on constrained hosts.

## What we can use in Lexicon

Ranked by value/effort ratio (high value first):

### 1. Permission-gated scheduling loops → `src/cron/scheduler.py`
**Value: HIGH / Effort: LOW**
`CronScheduler` already has session targeting and job lifecycle. Missing: owner scoping per job, self-paced (dynamic interval) mode, and routing heartbeat alerts to originating conversation rather than broadcast. The pattern is a direct extension of the existing `_execute_job()` dispatch — add a `session_owner` field and a "skip if unroutable" guard.

### 2. Channel message integrity / retry preservation → `src/gateway/session.py`
**Value: HIGH / Effort: MEDIUM**
Session lifecycle already manages queue lanes per agent, but there is no current evidence of message-preservation across retries or hook-triggered recovery. Adding a write-ahead buffer (pre-queue message log) that survives session teardown/restart would mirror the OpenClaw pattern. Entry point: the `pause`/`resume` path in `src/gateway/session.py`.

### 3. Bounded memory consolidation with provenance → `src/engine/memory/manager.py`
**Value: HIGH / Effort: MEDIUM**
`manager.py` coordinates memory layers. OpenClaw's pattern adds two things: (a) a background consolidation coroutine with a CPU/token budget cap, and (b) a `provenance` tag on each consolidated entry. Given Lexicon already has `episodic.py`, `working.py`, and `transcript_index.py`, the consolidation loop is the gap — it can run on a CronScheduler job targeting the `system` mode already supported.

### 4. CPU-scaled concurrency → `src/engine/orchestrator.py`
**Value: MEDIUM / Effort: LOW**
The orchestrator already fans out sub-agents. Replacing any hardcoded parallelism ceiling with `min(max(os.cpu_count() or 4, 8), 16)` is a one-liner that aligns with OpenClaw's approach and prevents over-scheduling in constrained cloud environments.

### 5. Automatic skill discovery → `src/engine/skills.py`
**Value: HIGH / Effort: HIGH**
Skills.py currently handles skill loading. Auto-discovery would add a post-session scanner that extracts reusable patterns, scores them, and creates skill drafts pending review. High effort because it requires a scoring heuristic and a review queue, but the payoff (Lexicon improves from its own sessions) is significant.

## Picks for what to spike next

1. **Permission-gated scheduling** — lowest effort, directly closes a known gap in `src/cron/scheduler.py`. Spike: add `owner_session_id` to `CronJob`, route heartbeat alerts via `src/engine/queue.py` to the owning session only.
2. **Bounded memory consolidation** — medium effort with high leverage. Spike: add a `consolidate` job in `src/cron/defaults.py` that calls a new `manager.consolidate(budget_tokens=2000)` method with provenance tagging in `src/engine/memory/manager.py`.
3. **Channel message retry buffer** — spike a write-ahead log in `src/gateway/session.py` that replays un-ACK'd messages on resume. Start with in-memory; promote to SQLite-backed once the interface is stable.
