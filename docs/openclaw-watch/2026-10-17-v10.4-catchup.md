## What's Notable

Five architectural patterns across this span are worth Lexicon's attention:

### 1. Quarantine malformed records at boot (2026.9.1)
Malformed legacy cron rows are isolated rather than blocking Gateway boot. Migration warnings degrade the service gracefully instead of stopping it. Previously, a single bad row could halt startup entirely.

### 2. Single failover owner for LLM retries (2026.9.1)
One owner process claims the failover decision for a given session. During persistent outages, the failure surfaces in `O(1)` provider cycles rather than cycling through every configured provider. Failover counters are emitted to console logs for observability.

### 3. Terminal refusals are not resent (2026.9.1)
Anthropic and other provider refusals are treated as final and are not placed back onto the retry queue. This ends the pattern of a refused turn generating repeated wasted calls.

### 4. Fenced cross-store memory commits (2026.10.5-beta.1)
Writes spanning multiple memory stores are fenced so that a partial publication — e.g. episodic store written, working memory not yet written — cannot leave a structurally inconsistent session state. Nightly dreaming and background sync continue running through plugin reloads.

### 5. Owner-first self-repair for failing automations (2026.10.5-beta.1)
When a scheduled automation fails, the automation's owner conversation attempts a repair turn before any alert is sent. A second repair turn runs if the error changes. Timeouts on the repair turn post a warning rather than silently failing.

## My Picks to Spike Next

**Spike 1 (1–2 days): LLM reliability trio** — items 1, 2, and 3 together. All are low-effort state/flag additions to existing modules. Together they eliminate retry storms, wasted calls on refusals, and boot failures from a bad cron row. Directly observable: failed call rates and startup reliability.

**Spike 2 (3–4 days): Fenced memory commits** — item 5. The current `src/engine/memory/manager.py` writes episodic and working memory in sequence with no rollback. A partial failure leaves the session in an inconsistent state. Adding a fence/rollback path is medium effort but prevents a class of silent data corruption.
