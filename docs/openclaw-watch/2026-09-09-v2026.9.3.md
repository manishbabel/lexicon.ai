## What's Notable

### 1. Warm Prompt Cache Preservation (2026.9.3)
OpenClaw now carries the LLM prompt cache across session boundaries rather than cold-starting each time. The runtime tracks a cache fingerprint per provider/model pair and reuses it when the prefix hasn't changed. Reduces first-token latency and provider cost for long-running agents.

### 2. Hot-Reload Settings for Agents, Models, Tools, Channels (2026.9.2)
The runtime watches config files with `inotify`/`FSEvents` and diffs only the changed section (agent definition, model binding, tool registration, channel config). Changed components reload in-place; unaffected components are untouched. No full restart needed.

### 3. Per-Agent Persistent Skill Collections (2026.9.3)
Each agent gets an isolated, named collection in the skill store that survives restarts. Skills can write keyed state into their collection (e.g. learned user preferences, cached lookups) without colliding across workspaces. Replaces a shared global skill state blob.

### 4. Reply Recovery After Gateway Restarts (2026.9.2)
In-flight reply state (partial streamed message, tool call chain) is written to a durable queue before each yield point. On restart the Gateway replays from the last durable checkpoint rather than dropping the turn. The session sees no gap.

### 5. Durable Tool Approvals (2026.9.1)
Tool approval decisions (allow once / always allow / deny) are now persisted per-agent and survive restarts. Previously granted approvals don't re-prompt on the next session. Stored as a signed, versioned record that can be revoked.

## What We Can Use in Lexicon

Ranked by value/effort. All file paths verified to exist in this repo.

### 🔴 HIGH value / MEDIUM effort

**A. Warm cache preservation → `src/engine/llm/`**
- Relevant files: `src/engine/llm/provider.py`, `src/engine/llm/claude_provider.py`, `src/engine/llm/router.py`
- Pattern: Tag each prompt with a cache fingerprint (hash of system prompt + stable prefix). On the next call, check if the fingerprint matches before sending; if so, let the provider's cache warm-start the completion. Claude's prompt caching already supports this at the API level — the work is fingerprint tracking in our router.
- Lexicon benefit: Cuts cold-start latency on repeated agent invocations (e.g. cron jobs, skill chains). `src/cron/scheduler.py` fires agents on schedule where this applies most.

**B. Hot-reload config → `src/shared/config.py`, `src/engine/registry.py`**
- Relevant files: `src/shared/config.py`, `src/engine/registry.py`, `src/gateway/server.py`
- Pattern: Add a file-watcher loop (watchdog or asyncio inotify) in `src/shared/config.py` that emits a `ConfigChanged` event. `src/engine/registry.py` subscribes and re-registers only the changed component. `src/gateway/server.py` handles channel config changes.
- Lexicon benefit: Live-tweak workspace definitions in `workspaces/` and agent model bindings without restarting the server. High DX value during development; also useful in prod for model routing changes.

### 🟡 MEDIUM value / LOW effort

**C. Per-agent skill collections → `src/engine/skills.py`**
- Relevant files: `src/engine/skills.py`, `workspaces/ai-educator/skills/`, `workspaces/software-engineer/skills/`
- Pattern: Namespace the skill state store by workspace/agent name. Each workspace (ai-educator, chief, software-engineer) gets its own key prefix in whatever persistence layer backs skill state today. Low lift if `src/engine/skills.py` already has a dict-based store.
- Lexicon benefit: Prevents ai-educator's cached lookups from polluting software-engineer's skill state as agent count grows.

### 🟡 MEDIUM value / MEDIUM effort

**D. Durable tool approvals → `src/engine/tools/registry.py`, `src/engine/hooks/`**
- Relevant files: `src/engine/tools/registry.py`, `src/engine/hooks/registry.py`, `src/engine/hooks/builtin.py`
- Pattern: Persist approval grants (tool name + agent id + grant level) in a small signed store alongside the hook registry. On startup, load and verify the store; inject pre-approved entries into the approval callback so they short-circuit without prompting.
- Lexicon benefit: Stops re-prompting for trusted tools like `src/engine/tools/vault_read.py` and `src/engine/tools/web_search.py` on every agent restart.

**E. Reply recovery after Gateway restarts → `src/gateway/session.py`, `src/gateway/router.py`**
- Relevant files: `src/gateway/session.py`, `src/gateway/router.py`, `src/engine/queue.py`
- Pattern: Write partial reply state to `src/engine/queue.py` (already exists as a queue abstraction) at each yield point. On restart, `src/gateway/session.py` checks the queue for an unfinished turn and resumes from the last checkpoint.
- Lexicon benefit: Prevents lost in-flight replies during deploys or crashes. Most impactful for long tool-chain turns (e.g. paper-reader runs via `src/engine/tools/paper_fetch.py`).

## Spike Picks

**Spike now: Warm cache preservation (A)**
Highest ROI for the least risk. Claude's API already supports prompt caching — the pattern is purely in our LLM router layer (`src/engine/llm/router.py`), touches no user-facing surface, and pays dividends immediately on the scheduled cron agents in `src/cron/scheduler.py`. A one-file spike in `src/engine/llm/claude_provider.py` could prototype the fingerprint logic.

**Spike next: Hot-reload config (B)**
Biggest DX improvement. The watchdog pattern is well-understood and the blast radius is limited to `src/shared/config.py` + `src/engine/registry.py`. Would eliminate the most common dev friction (restarting to pick up workspace edits).

**Defer: Reply recovery (E)**
Real value but requires careful queue semantics. `src/engine/queue.py` exists but its durability guarantees need audit first. Worth designing properly rather than patching quickly.
