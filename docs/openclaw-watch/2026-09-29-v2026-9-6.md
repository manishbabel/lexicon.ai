## What's notable

### 1. Workspace-scoped Memory and Skills provisioning (2026.9.x)
Remote workspaces now carry their own Files, Memory, and Skills context. Previously memory and skills were process-global; now each workspace session bootstraps its own isolated store. This is the most architecturally significant change: it enables per-user or per-project context isolation without forking the process.

### 2. Pluggable Decision Models / lightweight routing (2026.9.x)
"Optional Decision Models" let the runtime swap in TypeSafe Jev or local models for specific internal decisions (routing, classification, intent detection) while keeping the primary LLM for generation. Analogous to a cost/capability router that is first-class rather than hand-rolled.

### 3. Session integrity across retries and recovery (2026.9.5)
Explicit retry semantics on message delivery and crash recovery for unfinished work after restarts. Managed-update outcomes are now surfaced clearly in the session lifecycle rather than silently dropped or duplicated.

### 4. Gateway + plugin credential safety (2026.9.5 / 2026.8.33)
Credential handling was hardened across the Gateway layer and official plugin registry — specifically around how secrets are scoped to sessions and not propagated to tool calls that don't need them. The extended-stable backport of this suggests it was treated as a critical security fix.

### 5. Real-time streaming memory updates during live capture (2026.9.x)
Meeting notes (and equivalent live-capture flows) now update incrementally as capture continues rather than writing only on session close. This is a working-memory pattern: the transcript indexer feeds the memory store in a streaming fashion rather than batch.

## What we can use in Lexicon

Ranked by **value / effort** (H = High, M = Medium, L = Low).

| # | Pattern | Value | Effort | Lexicon files |
|---|---|---|---|---|
| 1 | Workspace-scoped memory isolation | H | M | `src/engine/memory/manager.py`, `src/engine/workspace.py`, `src/engine/skills.py` |
| 2 | Streaming transcript → working memory | H | L | `src/audio/transcription.py`, `src/engine/memory/working.py` |
| 3 | Credential scoping in Gateway (don't propagate secrets to tools) | H | L | `src/gateway/server.py`, `src/engine/tools/registry.py` |
| 4 | Router-level Decision Model (local/cheap model for classify/route) | M | M | `src/engine/llm/router.py`, `src/engine/llm/provider.py` |
| 5 | Session retry + recovery semantics | M | M | `src/engine/runner.py`, `src/gateway/session.py` |

### Detail

**#1 — Workspace-scoped memory.**  
`src/engine/workspace.py` already holds the workspace abstraction. `src/engine/memory/manager.py` currently does not scope stores by workspace. Porting this pattern means passing `workspace_id` through `MemoryManager` and routing episodic/working stores accordingly. `src/engine/skills.py` would gain a per-workspace skill registry lookup.

**#2 — Streaming transcript → working memory.**  
`src/audio/transcription.py` fires a callback per utterance. `src/engine/memory/working.py` is written as a batch store. Wiring the utterance callback directly to `working.py` write ops would give Lexicon live-updating working memory during audio sessions — very low risk, high payoff.

**#3 — Credential scoping.**  
`src/gateway/server.py` injects session config into tool calls. `src/engine/tools/registry.py` brokers tool invocations. The pattern: tools should receive only the credential keys they declare as required, not the full session secrets dict. This is a one-file guard in the registry.

**#4 — Decision Model router.**  
`src/engine/llm/router.py` already routes by model name. Extend it with a `decision_model` config key that points to a cheap/local provider for structured-output calls (classify, route, extract). No new abstraction needed — just a routing rule.

**#5 — Session retry/recovery.**  
`src/engine/runner.py` runs the agent loop. `src/gateway/session.py` tracks session state. Add an explicit `pending` / `recovering` state transition and a checkpoint write before each tool call so restarts can resume from the last completed tool rather than re-running from scratch.

## My picks to spike next

1. **#2 Streaming transcript → working memory** — lowest effort, immediately useful for audio sessions. One callback wire-up in `src/audio/transcription.py` feeding `src/engine/memory/working.py`.
2. **#3 Credential scoping** — low effort, directly reduces blast radius if a tool is compromised. Guard in `src/engine/tools/registry.py`.
3. **#1 Workspace-scoped memory** — medium effort but highest long-term value; blocks multi-user / multi-project isolation.
