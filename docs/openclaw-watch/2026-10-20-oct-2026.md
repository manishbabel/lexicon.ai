Between the June and October trains, OpenClaw shipped six minor stable trains (2026.6.x, 2026.7.x, 2026.8.x, 2026.9.x, 2026.10.x) plus the extended-stable LTS backport. This digest focuses on patterns introduced in the 2026.9.33 LTS and the 2026.10.10-beta series — the highest signal releases.

### 2026.9.33 Extended-Stable Headlines
- Work (automation turns, cloud worker claims, partial worker replies) resumes or persists after a Gateway restart.
- Long streamed replies whose text starts with a reply tag (e.g. `[[reply_to_current]]`) no longer re-parse the entire reply on every streaming delta.
- Cron no longer holds the shared state writer while waiting on host admission.
- State reads no longer stay closed until restart after a failed state cleanup.
- Doctor/update pipeline defers optional checks so critical update steps finish within older updaters' time limits.

### 2026.10.10-beta.2 Headlines
- `apply_patch` for multiple files is rejected before any file is written if a later target is missing or its context doesn't match — prevents partial workspace writes.
- Plugin `before_tool_call` hooks now fire in standalone `openclaw agent exec` sessions, not only interactive gateway sessions.
- Large cron job histories no longer exhaust the SQLite worker's memory.
- Buzz relay reconnects after a relay-side close during NIP-42 authentication.

### 2026.10.10-beta.1 Headlines
- Gateway database operations moved to worker threads (further Gateway responsiveness).
- Interrupted replies and queued turns resume after a Gateway restart.
- Cloud session management landed.

## What's Notable (Patterns Worth Porting)

### 1. Incremental streaming parse — avoid full-content re-parse on every delta
OpenClaw fixed a bug where any reply prefixed with a routing tag caused the entire reply buffer to be re-parsed on each streamed chunk. The fix separates tag detection (done once at stream open) from chunk dispatch. On long replies this was CPU-visible.

**Why it matters:** Any streaming path that looks at accumulated content on every delta has the same O(n²) shape. The fix pattern is: detect structured prefixes at stream start, set a flag, then dispatch bare chunks.

### 2. Persistent turn state — survive Gateway restarts
Automation turns, queued turns, and partial worker replies now write enough state to resume after a process restart, rather than being silently dropped. The pattern is a lightweight checkpoint written before blocking I/O, read back on startup to re-enqueue.

**Why it matters:** Lexicon's queue and runner have no restart-recovery path. Dropped in-flight turns are invisible failures.

### 3. Atomic multi-file workspace patch
Before writing any file in a multi-file patch, OpenClaw now validates every target (exists, context matches). If validation fails the entire patch is rejected — no partial writes. The pattern is a two-phase check: validate-all, then apply-all.

**Why it matters:** Partial writes that leave workspace in an inconsistent state are a silent correctness bug and hard to diagnose.

### 4. Hook dispatch in headless exec
Plugin `before_tool_call` hooks are now dispatched in both interactive (gateway) and headless (`agent exec`) sessions. The fix promotes hook dispatch from a gateway-layer concern to a session-layer concern.

**Why it matters:** Lexicon's hook registry is consulted at tool call time, but headless/CLI invocations bypass the gateway. Any policy or observability hook silently doesn't fire there.

### 5. Cron history bounded write
Large cron job histories were exhausting the SQLite worker's memory. The fix adds a cap on retained history rows and prunes old entries on write, rather than on read. Pruning on write keeps read latency flat.

**Why it matters:** Lexicon's cron store has unbounded history growth with no eviction policy.

## What We Can Use in Lexicon

Ranked by value/effort. All file paths verified to exist under `src/`.

| # | Pattern | Value | Effort | Lexicon files |
|---|---|---|---|---|
| 1 | Incremental streaming parse | HIGH | LOW | `src/gateway/server.py`, `src/gateway/protocol.py` |
| 2 | Cron history bounded write | HIGH | LOW | `src/cron/store.py` |
| 3 | Atomic multi-file workspace patch | HIGH | LOW | `src/engine/workspace.py` |
| 4 | Hook dispatch in headless exec | MEDIUM | LOW | `src/engine/hooks/registry.py`, `src/engine/hooks/builtin.py` |
| 5 | Persistent turn state (restart recovery) | HIGH | MEDIUM | `src/engine/runner.py`, `src/engine/queue.py` |

### Detail

**1 — Incremental streaming parse** (`src/gateway/server.py`, `src/gateway/protocol.py`)
Check whether the gateway's streaming path accumulates content and scans it on every delta. If it does, move any structured-prefix detection to stream open and dispatch raw chunks thereafter. Low-risk, high leverage on long turns.

**2 — Cron history bounded write** (`src/cron/store.py`)
Add a `MAX_HISTORY_ROWS` constant and a prune-on-write call after each job completion record is inserted. Target: keep the last N completions per job (e.g. 100). Prevents unbounded growth without changing read behavior.

**3 — Atomic multi-file workspace patch** (`src/engine/workspace.py`)
Before applying any writes in a batch, validate all targets. If any target file is missing or its expected context (surrounding lines) doesn't match, raise and abort — write none. Eliminates partial-write state.

**4 — Hook dispatch in headless exec** (`src/engine/hooks/registry.py`, `src/engine/hooks/builtin.py`)
Audit the registry's dispatch path: is it called from the session layer (runner/orchestrator) or from the gateway layer? If the latter, headless invocations skip hooks silently. Move dispatch to the session layer so all execution paths are covered.

**5 — Persistent turn state** (`src/engine/runner.py`, `src/engine/queue.py`)
Write a minimal checkpoint (session id, turn index, last tool call) to disk before blocking on LLM I/O. On startup, scan for incomplete checkpoints and re-enqueue. Medium effort but high correctness value for long-running sessions.

## My Picks for What to Spike Next

1. **Spike: cron history cap** — `src/cron/store.py`. Single file, self-contained, low risk. Add `MAX_CRON_HISTORY = 100` and a `DELETE ... WHERE rowid NOT IN (SELECT rowid FROM ... ORDER BY created_at DESC LIMIT ?)` after each insert. Done in an afternoon.

2. **Spike: streaming parse audit** — `src/gateway/server.py`. Read the streaming handler and check for accumulated-content scans on each chunk. If found, extract prefix detection to stream-open. The fix is a refactor, not new functionality.

3. **Spike: workspace patch atomicity** — `src/engine/workspace.py`. Wrap the current write loop in a validate-first pass. If workspace already has a single-file patch helper, this is a one-day change.
