## What's Notable

### 1. PostgreSQL-backed state (2026.11.5-beta.1)
OpenClaw's default in-process state store gained a first-class PostgreSQL backend with migration tooling and compatibility coverage. This is a production-grade durability upgrade — no more state loss on restart, and horizontal scaling becomes tractable.

### 2. Knowledge Scribes — reusable knowledge-capture workflows (2026.11.5-beta.1)
"Scribes" are declarative workflow definitions that run knowledge-capture pipelines: ingest → chunk → embed → store. They are first-class entities (not scripts bolted onto skills), with a reuse model that lets you share capture logic across agents.

### 3. Cron missed-slot recovery (2026.10.10-beta.5)
Stale `next_run` timestamps (caused by crash, restart, or clock drift) are no longer silently dropped. Missed slots are admitted on startup, with a configurable catch-up window. Prevents silent schedule gaps.

### 4. Gateway streaming fix — partial-tag stall (2026.10.10-beta.5)
Replies that contain tool-call-like XML or end on a partial HTML tag no longer stall the Gateway stream. The fix is a defensive flush-on-incomplete-tag approach in the streaming layer.

### 5. Security: redirect blocks & credential-log scrubbing (2026.11.1)
Two independent wins: (a) the Gateway now rejects chains that redirect into private/internal services (SSRF-class block); (b) credentials are scrubbed from several log paths and error messages that were leaking them.

## What We Can Use in Lexicon

Ranked by value/effort ratio (highest first):

### 1. Cron missed-slot recovery — HIGH value / LOW effort
**Map:** `src/cron/scheduler.py`, `src/cron/store.py`
OpenClaw's fix: on startup, compare `next_run` to `now`; if stale by more than one interval, run catch-up (bounded) and reset. Lexicon's `src/cron/scheduler.py` uses APScheduler-style next-fire tracking; `src/cron/store.py` persists state. Add a startup reconcile pass there.

### 2. Gateway redirect / SSRF block — HIGH value / LOW effort
**Map:** `src/gateway/router.py`, `src/gateway/server.py`
Lexicon's gateway routes external requests through `src/gateway/router.py`. Adding a middleware that refuses redirects to RFC-1918 / loopback targets closes an SSRF path with ~20 lines.

### 3. Credential-log scrubbing — HIGH value / LOW effort
**Map:** `src/shared/logger.py`
Lexicon's shared logger (`src/shared/logger.py`) is the single emission point. A scrubbing filter (regex over known secret patterns) on the handler catches leaks from any module.

### 4. Knowledge Scribes pattern — HIGH value / MEDIUM effort
**Map:** `src/engine/memory/episodic.py`, `src/engine/skills.py`, `src/engine/tools/`
Lexicon has episodic memory in `src/engine/memory/episodic.py` but no first-class ingest pipeline. A lightweight "scribe" abstraction — a named config that wraps fetch → chunk → embed → store — could sit in `src/engine/skills.py` or a new `src/engine/memory/scribe.py`.

### 5. PostgreSQL-backed memory — MEDIUM value / HIGH effort
**Map:** `src/engine/memory/manager.py`, `src/engine/memory/working.py`, `src/engine/memory/short_term.py`
Lexicon's memory layer uses in-process stores. Abstracting the persistence interface in `src/engine/memory/manager.py` and adding a Postgres adapter would enable durability + multi-process deployments. Effort is high; worth deferring until Knowledge Scribes (above) are in place.

### 6. Decision routing (ClawRouter) — MEDIUM value / MEDIUM effort
**Map:** `src/engine/llm/router.py`
OpenClaw added model selection based on declared media capability and routing hints. Lexicon already has `src/engine/llm/router.py` (LiteLLM + Claude + OpenAI providers). Porting the capability-aware dispatch (e.g., route vision tasks to media-capable models) is tractable.
