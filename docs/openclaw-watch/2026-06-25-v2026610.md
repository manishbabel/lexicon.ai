## What's notable

### 1. Automatic fast-mode routing (v2026.6.10)
OpenClaw detects whether a turn is _conversational_ (short acknowledgement, clarification, one-liner) vs. _substantive_ (research, generation, multi-step) and routes conversational turns to a cheaper/faster model tier, falling back to the full model if confidence is low. This is turn-type classification at the routing layer — not a persona setting but a per-call heuristic.

### 2. Session-aware cron targeting (v2026.6.10)
Before enqueuing a cron job targeting `session: main`, OpenClaw now checks whether an active session actually exists. Jobs configured to target the live user session skip gracefully (or re-queue) when no session is open, rather than enqueuing to a dead lane. This prevents ghost queue buildup during idle periods.

### 3. Hook registry trust composition (v2026.6.10)
When two hook registries are merged (e.g. built-in hooks + plugin hooks), OpenClaw ensures that a plugin handler registered at a low-trust tier cannot silently receive events intended for high-trust handlers. Each handler carries a `trust_level` annotation; `trigger()` enforces the ceiling.

### 4. Channel relay mode (v2026.6.11-beta.1)
Certain channel types can now relay messages (Slack→agent→Slack, Mattermost native commands) without a full WebSocket agent turn. The gateway routes matching message types directly to a relay path, bypassing the command queue entirely for low-latency channel interactions.

### 5. File-driven operator workflows (v2026.6.11-beta.1)
The CLI now accepts `--message-file <path>` pointing at a JSON/YAML file of structured commands, enabling batch operator workflows (e.g. seeding a session with pre-flight context, running a sequence of agent prompts). Useful for CI-driven automation and scripted demo setups.

## What we can use in Lexicon

Ranked by value/effort. Each entry maps to a verified file under `src/`.

### ★★★ 1. Turn-type fast-mode in `PersonaLLMRouter` — HIGH value / LOW effort
**File:** `src/engine/llm/router.py`

`PersonaLLMRouter.resolve()` currently selects provider+model solely from persona config. Adding an optional `turn_type: Literal["conversational", "substantive"] | None = None` parameter lets callers (the agent runner) pass a classification, and the router can map `conversational` turns to a lighter model alias (e.g. `haiku` alongside `sonnet` for the same provider). No schema changes needed — just an extra resolution step in `resolve()`.

**Spike:** Add `turn_type` param → if `conversational` and a `*_fast_model` setting exists for the persona, use it. One setting key, one `if` branch.

### ★★★ 2. Session-aware cron targeting in `CronScheduler` — HIGH value / LOW effort
**File:** `src/cron/scheduler.py`

`_execute_agent()` (line 266) always calls `self._enqueue_fn()` without checking whether a live session exists for `session == "main"` jobs. OpenClaw's pattern: inject a `session_liveness_fn: Callable[[str], bool]` into `CronScheduler.__init__()` (alongside the existing `_enqueue_fn`). Before enqueuing a `main`-targeted job, call it; if no session is active, either skip or re-queue with a short delay. Prevents dead-lane buildup for jobs like `__cron:daily_brief` that only make sense when the user is online.

**Spike:** Add `set_liveness_fn()` mirroring `set_enqueue_fn()`. Wire in `_execute_agent()` with a log-and-skip on miss.

### ★★ 3. Hook trust tiers in `HookRegistry` — MEDIUM value / MEDIUM effort
**File:** `src/engine/hooks/registry.py`

`register()` (line 78) accepts any handler with no trust annotation. OpenClaw's pattern adds a `trust: Literal["system", "plugin", "user"] = "system"` kwarg to `register()`, stored alongside the handler. `_resolve_handlers()` (line 149) then filters out handlers whose trust level exceeds the event's trust ceiling (passed through `trigger()`). Prevents a future plugin hook from receiving `tool:after:vault_write` events meant only for system handlers.

**Spike:** Add trust annotation to `HookHandler` wrapper dataclass; filter in `_resolve_handlers()`. No change to existing callers (default `system` is backward compatible).

### ★★ 4. Channel relay path in `MessageRouter` — MEDIUM value / HIGH effort
**File:** `src/gateway/router.py`

`dispatch()` (line 83) routes every message through session lookup + queue. For short-lived relay interactions (Slack slash commands, channel pings), OpenClaw skips the queue and handles synchronously in the router. In Lexicon this would mean adding a `relay` lane in `dispatch()` for a new `ChannelRelayMessage` type — routing it directly to an outbound channel adapter rather than the `CommandQueue`. Requires new `src/gateway/protocol.py` message types and a channel adapter interface.

### ★ 5. File-driven gateway CLI — LOW value / LOW effort
**File:** `src/gateway/server.py`

The `--message-file` pattern is straightforward to add as a CLI flag that reads a JSON array of `ClientMessage`-compatible dicts and injects them into the gateway on startup. Useful for demo scripting and CI smoke tests but not architecturally significant for Lexicon's current stage.
