## What's notable

### 1. Event-driven scheduling
OpenClaw's scheduler now supports a change-detection predicate: a job sleeps until an observable changes rather than waking unconditionally every tick. This is a low-coupling interface — the scheduler checks a registered callback before executing, so jobs opt in without restructuring their implementation.

### 2. Gateway crash recovery with stable repair path
Instead of catching a panic and immediately restarting (which loops if the root cause persists), the Gateway now backs off, logs the failure state, and enters a supervised repair routine before re-accepting connections. This separates restart policy from crash detection.

### 3. Security boundary enforcement on provider/plugin output
Untrusted provider and plugin responses are now filtered at the point of ingestion — before they reach the context window or skill routing. The 2026.6.34 note is explicit: "loopback provider endpoints now reject unsafe access paths." This is a strict input-validation layer on LLM and tool responses, not a general WAF.

### 4. Idempotent channel acknowledgements
Channels attach an idempotency key to each delivery acknowledgement so that pending work queued before a restart is not re-delivered or lost — the gateway replays from the last un-acknowledged item. This is a standard at-least-once delivery with dedup, applied to the channel layer.

### 5. Crash-recoverable memory snapshots (beta)
The quarantine store isolates corrupt or schema-mismatched memory before it can propagate, and SQLite snapshots are written with enough journalling to recover after an unclean shutdown. Schema upgrades are rejected if they would lose data — the agent surface this as an error rather than silently dropping rows.

### Detail

**1. Event-driven scheduling → `src/cron/scheduler.py`**  
Lexicon's scheduler fires jobs on a fixed interval (`src/cron/scheduler.py`). Adopting a change-detection predicate means adding an optional `when_changed` callback to the job definition; the scheduler calls it before executing and skips if it returns `False`. The store (`src/cron/store.py`) already tracks job metadata, so the predicate result can be persisted with minimal schema change.

**2. Gateway crash recovery → `src/gateway/server.py`**  
The gateway server currently restarts on failure. A supervised repair path would: (a) catch the exception, (b) emit a structured error event, (c) back off with a cap, (d) re-run a health check before accepting new connections. The restart logic is self-contained in `src/gateway/server.py`.

**3. Provider/plugin output validation → `src/engine/llm/provider.py` · `src/engine/tools/registry.py`**  
LLM provider responses flow through `src/engine/llm/provider.py` before reaching the runtime. A filtering step here — checking for prompt-injection markers, oversized payloads, or disallowed paths — requires no downstream changes. Tool responses from `src/engine/tools/registry.py` are a separate surface and need the same treatment before they enter the context.

**4. Idempotent channel ACKs → `src/gateway/session.py`**  
Session state in `src/gateway/session.py` would need a delivery-cursor field (last acknowledged message ID). On restart, the session replays from that cursor. The ACK write should be transactional with the work dispatch.

**5. Memory quarantine → `src/engine/memory/manager.py`**  
The memory manager in `src/engine/memory/manager.py` could adopt a staged write pattern: write to a quarantine buffer first, validate the schema, then promote to main storage. This is beta-stage in OpenClaw; worth watching but not urgent.
