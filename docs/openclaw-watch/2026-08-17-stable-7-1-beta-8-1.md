## What's notable

### 1. Secret egress host binding (2026.8.1-beta.2 · security)
Each shared-store secret is now bound to an exact HTTPS destination host. If a tool or plugin tries to send a secret to an unregistered host, substitution fails closed before plaintext egress — forged-marker / web-search boundary bypass is explicitly called out as a patched vector. This is a first-class security primitive, not a log filter.

### 2. Durable channel delivery with dead-letter recovery (2026.7.2-beta.7 · channels)
Channel messages survive process restarts via a shared ingress drain and a dead-letter queue. Undelivered messages are replayed on startup rather than dropped. Previously each channel was fire-and-forget; the DLQ pattern converts a best-effort pipe into an at-least-once guarantee.

### 3. Session rewind and branching (2026.7.2-beta.7 · runtime)
Sessions can be rewound to a named checkpoint and forked from that point, creating parallel conversation branches. The checkpoint is serialized alongside the context compaction state, so branches share history up to the fork point but diverge independently from there.

### 4. Cross-agent active-memory recall with external import (2026.7.1 · memory)
Fast active-memory recall is now cross-conversation by default for personal installs. Users can import memory from Claude Code, Codex, and Hermes via a unified settings interface. Retrieval operates across all sessions, not just the current one, using a global transcript index.

### 5. Atomic model + runtime switching (2026.8.1-beta.2 · LLM routing)
Model, runtime, and thinking mode can now be switched mid-session without restart. The router maintains a live provider registry that accepts hot-swap commands; the active turn completes on the old model, then subsequent turns use the new one.

## What we can use in Lexicon

Ranked by value/effort. Every path below was verified against `src/` in this repo.

---

### #1 — Secret egress host binding · `src/shared/config.py` + `src/engine/tools/web_search.py`
**Value: high · Effort: medium**

API keys in `src/shared/config.py` are stored as bare strings (e.g., `tavily_api_key: str = ""`). Nothing prevents a prompt injection or a buggy tool from exfiltrating a key to an unexpected host. OpenClaw's pattern: bind each key to an allowlist of destination hosts at load time; the tool call layer checks the resolved host against the binding before substituting the secret into the request.

Concrete spike: add a `bound_hosts: dict[str, list[str]]` section to `Settings` (or the `~/.lexicon/config.json` schema) mapping key names to HTTPS host allowlists. In `src/engine/tools/web_search.py` (the one tool that currently reads `tavily_api_key` and makes outbound HTTPS calls), check the request URL host against the allowlist before injecting the key. Fail closed with a `PermissionError` on mismatch.

---

### #2 — Durable session persistence (dead-letter recovery) · `src/gateway/session.py` + `src/gateway/server.py`
**Value: high · Effort: medium**

`SessionManager` in `src/gateway/session.py` holds all session state in `self._sessions: dict[str, SessionState]` — pure in-memory. A process restart silently drops every active session and its lane key. The dead-letter pattern OpenClaw adopted converts this to an at-least-once store: sessions are written to a durable store (SQLite or JSONL) on every state transition and reloaded on startup; incomplete command deliveries are replayed from the dead-letter log.

Spike: add a `SessionStore` alongside `src/cron/store.py` (which already implements the JSONL-persist pattern for cron jobs) and wire `SessionManager` to write on `create_session`, `pause_session`, `resume_session`, and `end_session`.

---

### #3 — Atomic model switching mid-session · `src/engine/llm/router.py`
**Value: medium · Effort: low**

`PersonaLLMRouter.resolve()` is stateless and re-resolves on every call, but there is no way for a running agent to request a model change that takes effect on the next turn without restarting the session. Adding a `switch(persona, provider, model)` method that mutates the cached `_providers` dict and returns a new `ResolvedLLM` would expose this in ~20 lines. Downstream, `src/engine/runner.py` would need to pick up the updated resolution between turns rather than once at session start.

---

### #4 — Cross-conversation memory recall · `src/engine/memory/transcript_index.py` + `src/engine/memory/manager.py`
**Value: medium · Effort: high**

`MemoryManager.recall()` in `src/engine/memory/manager.py` searches `ShortTermMemory` scoped by `agent_id` — memories from other personas or past sessions are invisible. OpenClaw's global transcript index allows any session to recall from the unified pool. Lexicon already has `src/engine/memory/transcript_index.py`; the spike would be wiring it into `MemoryManager.recall()` as a fifth search layer (`include_transcript_index: bool = False` to stay opt-in) and populating the index from `store_interaction()`.

Dedup is the key risk: the current `_deduplicate()` uses exact 100-char prefix matching — cross-agent recall will need semantic dedup (embedding cosine) to avoid flooding context with near-duplicate entries from different sessions covering the same topic.

---

### #5 — Session checkpoint + branch · `src/engine/context/compactor.py`
**Value: medium · Effort: high**

Session branching requires the compacted context to be serializable to a named checkpoint. `src/engine/context/compactor.py` manages context pruning today but has no snapshot/restore interface. The effort is substantial: need a checkpoint format, branch-aware session IDs in `src/gateway/session.py`, and branch isolation in memory layers. Worth watching how OpenClaw's implementation stabilizes in beta before spiking.

## My picks for what to spike next

1. **Spike `#1` (secret egress binding)** — closes a real security gap with contained scope. Two files, no schema migration.
2. **Spike `#2` (session durability)** — the in-memory session dict is a reliability hole. The `CronJobStore` pattern in `src/cron/store.py` already shows the JSONL approach works; session persistence is straightforward to port.
3. **Watch `#3` (atomic model switching)** — low effort once `src/engine/runner.py` pickup semantics are clarified; good candidate for the session after the above two.
