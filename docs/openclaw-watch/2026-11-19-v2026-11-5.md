## What's notable (patterns worth porting)

### 1. `maxSummaryChars` — bounded compaction output
OpenClaw added a `maxSummaryChars` config that caps how large a compaction summary can grow. Without it, an LLM summarizing a long conversation can produce a summary nearly as large as the original, defeating the purpose. The setting is enforced by the compactor before the summary is spliced back into the message list.

### 2. Provider rate-limit respect vs local backoff accumulation
Before 2026.11.1 OpenClaw used local exponential backoff; under sustained load this accumulated to hours. The fix: read the `Retry-After` / `x-ratelimit-reset-requests` headers from the provider response and sleep exactly that long instead of doubling a local counter. This cuts unnecessary wait time under burst load.

### 3. Session tool definition stability for prompt-cache hits
Also in 2026.11.1: tool definitions were serialised freshly each turn, causing cache misses on every request even when the tool set had not changed. Fix: derive the serialised form once per session bootstrap and reuse it until tools are explicitly updated. High-leverage on Claude and other providers that offer prompt caching.

### 4. Cron scheduler resilience — deadline/account persistence across restarts
In 2026.11.5: retry deadlines and account selection are now checkpointed to the job store, not held in memory. Late scheduler wakeups are handled gracefully (jobs are not silently dropped). Disabling automatic scheduling releases idle worker threads immediately.

### 5. Automation memory-access recheck before execution (security)
Queued cron/automation runs now recheck whether the originating session still has access to the private memory they were scheduled against before they execute — prevents stale automations from reading memory the owner has since restricted.

## What we can use in Lexicon

Ranked by estimated value / effort:

| # | Pattern | Value | Effort | Lexicon file(s) |
|---|---------|-------|--------|-----------------|
| 1 | Provider rate-limit respect | HIGH | LOW | `src/engine/llm/router.py` |
| 2 | `maxSummaryChars` cap | HIGH | LOW | `src/engine/context/compactor.py` |
| 3 | Session tool definition stability | MEDIUM | LOW | `src/engine/runtime.py` |
| 4 | Cron deadline/account persistence | MEDIUM | MEDIUM | `src/cron/scheduler.py`, `src/cron/store.py` |
| 5 | Pre-run memory access recheck | MEDIUM | LOW | `src/cron/scheduler.py` |

**Details:**

**1. Provider rate-limit respect → `src/engine/llm/router.py`**  
Lexicon's router currently has no `Retry-After` handling. Add a `_retry_after(response_headers)` helper in `PersonaLLMRouter` that extracts the provider's reset time and sleeps exactly that long before retrying. This prevents the multi-hour backoff spiral under burst load.

**2. `maxSummaryChars` → `src/engine/context/compactor.py`**  
The compactor has `COMPACTION_THRESHOLD` and `PROTECTED_TAIL` constants but no limit on summary output length. Add a `MAX_SUMMARY_CHARS` constant (e.g. 2000) and truncate/request a shorter summary when the LLM-produced summary exceeds it. Keep the active human request intact across repeated compactions (also from 2026.11.1).

**3. Session tool definition stability → `src/engine/runtime.py`**  
If `runtime.py` serialises tool schemas on every turn, cache the serialised form at session init and invalidate only when the tool set changes. This is a high-leverage win on the Claude provider (`src/engine/llm/claude_provider.py`) which supports prompt caching.

**4. Cron deadline/account persistence → `src/cron/scheduler.py` + `src/cron/store.py`**  
Checkpoint retry deadlines and target-account into `src/cron/store.py` (which already manages job persistence) so they survive a Gateway restart. Add a late-wakeup guard: if a scheduled fire is overdue by more than the job's interval, skip rather than run a pile-up.

**5. Pre-run memory access recheck → `src/cron/scheduler.py`**  
Before `_execute_job()` hands off to the agent runtime, call a lightweight check that the originating workspace still has read access to the memory the job was scoped to.
