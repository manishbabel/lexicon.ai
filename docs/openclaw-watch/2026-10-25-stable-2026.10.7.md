## What's Notable

### 1. `next_check` — authority-preserving one-shot continuation (2026.10.6)
A scheduled continuation can call `next_check` to register a follow-up firing rather than relying on a separate cron entry. The key architectural twist: the follow-up inherits the _operator authority_ of the turn that scheduled it. This eliminates a class of permission-downgrade bugs where a cron-re-entry lost its originating context.

### 2. Validate-then-apply for patch operations (2026.9.34, PR #160409)
`apply_patch` now inspects the entire ordered hunk envelope before touching the workspace. A malformed later hunk can no longer leave the workspace in a partially-mutated state from successful earlier hunks. Straight defensive transaction semantics applied to a file-mutation tool.

### 3. Memory re-import preserves human-authored content (2026.9.34 + 2026.10.7, PR #175707)
Reimporting OKF concepts previously silently dropped notes that users had written by hand. The fix distinguishes auto-generated from user-authored records and merges rather than overwrites. Pattern: memory stores need a `user_authored` flag (or equivalent) to protect hand-crafted content through refresh cycles.

### 4. Session recovery with provenance (2026.10.7)
Interrupted sessions now track which recovery event they came from. Delivery of queued turns and child results across restarts is deduplicated — the same item isn't re-enqueued after a crash (2026.10.6).

### 5. Extended-stable / LTS-gated release line (2026.9.34)
OpenClaw now ships a gateway-only "extended-stable" branch that backports security + critical fixes selectively (142 applied, 82 adapted, 391 excluded from the 2026.10 line). This is a deployment-strategy pattern, not a code pattern, but relevant for how Lexicon ships production builds.

## What We Can Use in Lexicon

Ranked by value/effort (high value first):

### A. `next_check` continuation pattern → `src/cron/scheduler.py`
**Value: High / Effort: Medium**  
`CronScheduler` already wraps APScheduler with `DateTrigger` for one-shot firings. Adding a `schedule_followup(job_id, delay, authority_context)` method on `CronScheduler` would let a running job re-register itself without losing the authority chain. Today any job that wants to "check back in 5 minutes" must write a new top-level cron entry, which drops the originating operator context.

### B. Validate-then-apply for `vault_write` → `src/engine/tools/vault_write.py`
**Value: High / Effort: Low**  
`vault_write` currently applies changes incrementally. Adding a dry-run validation pass (verify all paths exist, all content is well-formed) before the first write makes partial-write failures impossible. Small surface area — the tool is self-contained.

### C. User-authored content protection in memory re-imports → `src/engine/memory/manager.py`
**Value: Medium / Effort: Medium**  
`MemoryManager` pulls from QMD vault search (knowledge base) which is refreshed on re-import. A `user_authored: bool` field on `ShortTermEntry` / `EpisodicEntry` (see `src/engine/memory/short_term.py`, `src/engine/memory/episodic.py`) combined with a merge-not-overwrite path in the QMD refresh would prevent hand-written notes from being dropped.

### D. Delivery deduplication across restarts → `src/engine/queue.py`
**Value: Medium / Effort: Medium**  
OpenClaw's fix prevents queued turns from re-enqueuing after a crash. Lexicon's `src/engine/queue.py` should be audited: if the scheduler restarts while a job is in flight, can the same job fire twice? Adding an idempotency key on enqueued items (content hash or UUID stored in `CronJobStore`) closes this.

### E. Recovery provenance tagging → `src/engine/runtime.py`
**Value: Low / Effort: Low**  
Tag the `AgentRuntime` (or `Runner` in `src/engine/runner.py`) with the recovery event ID when it's initialized from a interrupted-session restore. Low priority but useful for post-mortems.
