## What's Notable

### 1. Per-job dynamic cadence scheduling
OpenClaw's cron layer now supports per-job runtime cadence overrides: jobs can self-report how often they need to run next based on their last result, and monitors can adjust their own polling interval. Previously cadences were static at registration time.

### 2. Quarantine store for memory safety
The primary database is now backed by a quarantine store: on schema-upgrade or detected corruption, the engine rejects data-lossy migrations and quarantines the damaged store rather than silently corrupting it. SQLite snapshots are written crash-recoverably before any migration.

### 3. Session rewind and branching
Users can rewind to any prior transcript message and fork a new branch from it, with branch switching preserved across platforms and prompt images carried through forks. This introduces an explicit tree model for conversation history.

### 4. Durable channel delivery with dead-letter recovery
Messages that fail delivery are now durably queued in a dead-letter store and replayed after restart. The shared ingress drain ensures no message is lost across gateway restarts. Covers Telegram, Signal, Slack, and others.

### 5. Gateway crash-loop resolution
Instead of indefinite restart loops, the gateway now transitions to a degraded-state mode on repeated startup failures, surfaces diagnostics, and halts rather than consuming resources in a tight loop.

## What We Can Use in Lexicon

Ranked by **value / effort** (H = High, M = Medium, L = Low).

### 1. Per-job dynamic cadence — `src/cron/scheduler.py` · Value H / Effort L

Lexicon's scheduler (`src/cron/scheduler.py`, `src/cron/store.py`) uses fixed cadences registered in `src/cron/defaults.py`. OpenClaw's pattern: each job's run function returns an optional `next_run_in` hint that the scheduler respects for the next tick. This is an additive change — the scheduler falls back to the static cadence when no hint is returned.

**Spike:** Add an optional `cadence_hint` return value to the `CronJob` protocol in `src/cron/scheduler.py`; update `src/cron/store.py` to persist per-job overrides.

### 2. Quarantine store for memory manager — `src/engine/memory/manager.py` · Value H / Effort M

`src/engine/memory/manager.py` is the central store for episodic and working memory. The OpenClaw pattern: before any schema migration, snapshot the current store to a `.quarantine` path; if the migration would be data-lossy, reject it and keep the quarantine copy rather than proceeding. This prevents silent memory corruption on upgrades.

**Spike:** Add a `_snapshot_before_migrate()` hook in `src/engine/memory/manager.py`; define a `DataLossyMigrationError` that the migration runner catches.

### 3. Session branching — `src/engine/memory/episodic.py` · Value M / Effort M

`src/engine/memory/episodic.py` stores the linear transcript. OpenClaw's tree model stores a `parent_message_id` per entry and a `branch_id` per session slice, enabling rewind by switching the active branch pointer. Lexicon's `src/engine/memory/working.py` tracks current session state and would need a `branch_id` field.

**Spike:** Add `branch_id` and `parent_message_id` to `src/engine/memory/episodic.py`'s entry schema; add `set_branch(branch_id)` to `src/engine/memory/working.py`.

### 4. On-demand cron activation — `src/cron/scheduler.py` · Value M / Effort L

OpenClaw's 2026.7.1 lets scheduled jobs be triggered manually without waiting for their next tick. In Lexicon `src/cron/scheduler.py` exposes a `run_job(job_id)` that could be called directly — the gap is surfacing it through the runtime. Wiring `src/engine/orchestrator.py` to call `run_job` on a tool invocation would close this.

**Spike:** Expose a `trigger_cron_job` tool in `src/engine/tools/registry.py` that calls `scheduler.run_job(job_id)` directly.

### 5. Dead-letter recovery for gateway — `src/gateway/session.py` · Value M / Effort M

`src/gateway/session.py` manages active sessions; messages that fail mid-delivery are currently dropped. OpenClaw's dead-letter pattern appends undelivered messages to a per-session queue file; on reconnect the session drains the queue before accepting new messages. `src/gateway/router.py` would need to call `drain_dead_letter(session_id)` on session resume.

**Spike:** Add a dead-letter queue (simple append-only file or SQLite table) to `src/gateway/session.py`; hook `src/gateway/router.py` to drain it on reconnect.

## My Picks for What to Spike Next

**Immediate (this sprint):**

1. **Per-job dynamic cadence** (`src/cron/scheduler.py`) — lowest effort, direct win for any workspace agent that self-regulates its polling. The `src/cron/defaults.py` + `src/cron/scheduler.py` surface is small and well-contained.

2. **Quarantine store** (`src/engine/memory/manager.py`) — memory corruption on schema upgrade is a production risk today; this is defensive hardening with high payoff. Pair with a migration test.

**Next sprint:**

3. **On-demand cron activation** (`src/engine/tools/registry.py` + `src/cron/scheduler.py`) — enables the workspaces under `workspaces/` to trigger their own scheduled tasks mid-conversation, which is a natural capability gap right now.

**Backlog / research:**

4. Session branching — architecturally significant; deserves a design doc before implementation since it touches `src/engine/memory/episodic.py`, `src/engine/memory/working.py`, and transcript display in the gateway.

5. Dead-letter recovery — valuable but only relevant once Lexicon's gateway serves external channel traffic at volume.
