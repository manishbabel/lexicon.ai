## What's Notable

### 1. Dreaming — Background Memory Consolidation (2026.8.1)
A background process promotes provenance-tagged episodic fragments to long-term memory after sessions end. Includes a Dream Diary for auditability and `memory forget` to remove derived memories without touching source transcripts. Bounded personal context is retrieved by default on personal installs; groups/channels excluded.

**Why it matters:** Lexicon stores episodic records (`src/engine/memory/episodic.py`) but has no background promotion path. High-value conversations degrade silently once the working window is full.

### 2. Queue Durability — Interrupted Reply Resume (2026.10.10-beta.1)
Queued turns, interrupted replies, and watched child results now survive Gateway restarts. The runtime writes resume state before processing each turn and clears it on clean completion.

**Why it matters:** Lexicon processes queued messages in `src/engine/queue.py` with no crash-recovery guarantee. A restart drops in-flight turns silently.

### 3. Cron Rate-Limit Retry (2026.6.1)
Recurring cron jobs automatically retry after transient model 429s using an exponential back-off and reschedule within the same tick window.

**Why it matters:** `src/cron/scheduler.py` has no retry logic for LLM rate limits. Jobs that hit a spike fail permanently until the next scheduled window.

### 4. Per-Run Model Fallback Overrides (2026.10.10-beta.1)
Runtime accepts a `fallback_models` list per run; on provider errors the engine cycles through them transparently without surfacing the failure to the agent.

**Why it matters:** `src/engine/llm/router.py` routes to a single provider. Multi-provider fallback is manual and requires reconfiguration.

### 5. Gateway DB onto Worker Threads (2026.10.x)
SQLite writes from session and transcript management are dispatched to dedicated worker threads, reducing main-thread stalls during heavy transcript I/O.

**Why it matters:** `src/gateway/session.py` and `src/gateway/server.py` do storage writes synchronously. Under high message volume this serialises the event loop.

## What We Can Use in Lexicon

Ranked by value / effort (High/Medium/Low each):

| # | Pattern | Value | Effort | Lexicon target |
|---|---------|-------|--------|----------------|
| 1 | Cron rate-limit retry with back-off | High | Low | `src/cron/scheduler.py` |
| 2 | Queue durability / resume-after-restart | High | Medium | `src/engine/queue.py`, `src/engine/runtime.py` |
| 3 | Per-run model fallback list | Medium | Low | `src/engine/llm/router.py` |
| 4 | Background episodic → long-term promotion | High | High | `src/engine/memory/episodic.py`, `src/engine/memory/manager.py` |
| 5 | Gateway DB worker-thread offload | Medium | Medium | `src/gateway/session.py`, `src/gateway/server.py` |

### Details

**1 — Cron rate-limit retry** (`src/cron/scheduler.py`, Low effort)
Catch `RateLimitError` in the scheduler's `_run_job` path. Reschedule within the current tick window using exponential back-off (2s, 4s, 8s, cap 30s). Add a `max_retries` field to the job record in `src/cron/store.py`. Defaults module (`src/cron/defaults.py`) exposes the retry cap.

**2 — Queue durability** (`src/engine/queue.py`, Medium effort)
Before dequeuing a turn, write a `pending_turn` row to a lightweight SQLite resume table (can reuse the store pattern already in `src/cron/store.py`). On clean completion, delete the row. On startup, `src/engine/runtime.py` reads any pending rows and requeues them. Requires idempotent tool calls or at-least-once semantics acknowledged at the tool layer.

**3 — Per-run model fallback** (`src/engine/llm/router.py`, Low effort)
`router.py` already selects a provider by model name. Extend the `RunConfig` (or equivalent context object) with `fallback_models: list[str]`. In `router.py`, wrap the `complete()` call; on `ProviderError` or `RateLimitError`, pop the next model from the list and retry once. No changes to individual providers.

**4 — Background episodic promotion** (`src/engine/memory/episodic.py` + `manager.py`, High effort)
Create a background worker (thread or async task) that reads high-signal episodic fragments (e.g. episodes with `importance >= threshold`) and writes them to the long-term store via `src/engine/memory/manager.py`. Provenance: record source `session_id` and `episode_id`. Trigger on session close or a time-based heartbeat in `src/engine/heartbeat.py`. Keep a `derived_from` field so deletions cascade.

**5 — Gateway worker-thread offload** (`src/gateway/session.py`, Medium effort)
Wrap `session.py`'s transcript and state persistence calls in a simple worker thread queue (stdlib `queue.Queue` + `threading.Thread`). Writes become fire-and-forget from the event loop; reads remain synchronous. Flush the queue on `server.py` shutdown.

## My Picks for What to Spike Next

1. **Cron rate-limit retry** (`src/cron/scheduler.py`) — Smallest scope, high operational value. A single try/except with a requeue call. Verifiable in tests without infra changes.

2. **Per-run model fallback** (`src/engine/llm/router.py`) — Also narrow. Adds resilience during provider outages without changing the existing routing logic or provider implementations.

These two together improve reliability at the scheduling and LLM layers with under a day's work. Queue durability is the next highest-leverage pick but deserves its own spike given idempotency design decisions needed.
