## What's Notable

### 1. Gateway fault-tolerance: crash-loop → stable repair path
"Repeatedly failing Gateways now leave a stable repair path instead of restarting indefinitely."
OpenClaw replaced infinite-restart logic with a circuit-breaker: after N consecutive failures the Gateway enters a *control-plane-safe* mode that surfaces repair diagnostics instead of looping. This is a direct architectural improvement to production resilience.

### 2. Exit-triggered cron schedules
A new scheduling primitive fires a job when a session exits cleanly (e.g. flush buffers, publish a summary, trigger follow-up). Previously schedules were time-only (cron/interval/date). This fills the gap for "do X when a long-running session finishes" patterns without polling.

### 3. Conversational onboarding via agent-loop (Crestodian)
Setup flow is now driven by a dedicated onboarding agent (`Crestodian`) that validates connections before saving and preserves state across interruptions. The pattern: an opinionated workspace whose sole purpose is guided first-run. Demonstrates agent-as-wizard rather than a static form/config file.

### 4. Sub-agent delegation with tracked results
Codex delegation and native subagents now return structured result manifests (which sub-agent ran, return value, duration) rather than raw strings. `openclaw attach` gives a connected coding agent temporary scoped access to the parent session. Improves observability and partial-failure handling in multi-agent flows.

### 5. Untrusted provider/plugin response validation
LLM responses coming from external/third-party providers are now validated before being returned to the orchestrator layer. Combined with credential masking in logs and approval-binding per operation, this is a defence-in-depth pass on the provider boundary.

## What We Can Use in Lexicon

Ranked by **value / effort** (H = high, M = medium, L = low).

### A. Gateway circuit breaker — value H / effort L
**Pattern:** After N consecutive WebSocket or startup failures, stop restarting and enter a degraded-but-stable mode that logs the failure reason and waits for operator intervention.
**File:** `src/gateway/server.py`
Current server creates services in the FastAPI lifespan context manager with no restart guard. Adding a failure counter + exponential backoff with a halt after threshold is a small, self-contained addition to the lifespan block.

### B. Exit-triggered cron jobs — value M / effort L
**Pattern:** Register APScheduler jobs that fire on session-exit events, not just on a time trigger.
**File:** `src/cron/scheduler.py`
The scheduler already wraps `CronTrigger`, `DateTrigger`, and `IntervalTrigger`. Add a fourth trigger type backed by an asyncio `Event` set by the gateway's shutdown hook — wires naturally into the existing `_execute_job` path.

### C. Sub-agent result manifests — value M / effort M
**Pattern:** Wrap sub-agent return values in a structured manifest: `{agent_id, workspace, duration_ms, output, error}` instead of raw string. Log manifests for observability.
**File:** `src/engine/orchestrator.py`
The `Orchestrator` already runs sub-agents and collects `AgentOutput`. Adding a thin manifest dataclass around the existing return is low-risk and enables future partial-failure recovery without changing the protocol.

### D. LLM provider response validation — value H / effort M
**Pattern:** After the LLM returns a message, run a lightweight structural check (non-empty, no credential-shaped strings, no prompt-injection markers) before passing it upstream.
**Files:** `src/engine/llm/provider.py`, `src/engine/llm/router.py`
Both the abstract `LLMProvider` base and the `PersonaLLMRouter` are good injection points. A validation hook on the provider base class keeps it consistent across Claude, OpenAI, and LiteLLM backends.

### E. Session checkpoint recovery — value H / effort H
**Pattern:** Persist a lightweight checkpoint (last N turns + active skill context) after each assistant turn. On restart, load the checkpoint and resume rather than starting cold.
**Files:** `src/engine/memory/transcript_index.py`, `src/engine/memory/episodic.py`
`transcript_index.py` already indexes turns; `episodic.py` manages longer-term memory. Adding periodic checkpoint writes to `episodic` plus a `resume_from_checkpoint()` path is the highest-value item but touches the most surface area.

## My Picks for What to Spike Next

1. **Gateway circuit breaker (A)** — Highest bang-for-buck. One afternoon of work, immediate production resilience gain, no protocol changes. Spike: add a `_restart_count` counter to `server.py`'s lifespan, halt after 5 consecutive failures, emit a `gateway.failed` hook event.

2. **LLM provider response validation (D)** — Hidden risk right now: external providers (LiteLLM passthrough, OpenAI) return unsanitised content. A simple hook on `LLMProvider.complete()` closes the gap before Lexicon gets more users.

3. **Exit-triggered cron (B)** — Low effort unlock for flush/summarise patterns that workspaces like `software-engineer` could use immediately (e.g. end-of-session knowledge consolidation via `workspaces/software-engineer/skills/knowledge-consolidator/SKILL.md`).
