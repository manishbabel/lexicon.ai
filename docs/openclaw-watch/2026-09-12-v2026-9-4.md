## What's notable (architectural patterns)

### 1. Reply recovery after stream interruption
**2026.9.4** added logic to distinguish stream termination, tool errors, and normal completion — recovering final replies after interrupted streams, retaining timeout notices across reload, and deduplicating final answers when live chat hands off to persisted history. This is a first-class conversation durability model, not just retry logic.

### 2. Agent-owned skills (one Workshop per agent)
**2026.9.3** shifted skill persistence from workspace scope to agent scope: one writable Workshop collection per agent. Skills survive workspace transitions; a Doctor migration tool handles safe promotion of legacy workspace-owned skills. Decouples skill storage from session/workspace lifecycle.

### 3. Read-only deployment mode (`OPENCLAW_CONFIG_READONLY=1`)
**2026.9.4** introduced a single env var that prevents config rewrites in operator-managed deployments while preserving diagnostics and ordinary runtime state. Clean ops/runtime boundary: operators own config, agent owns diagnostics.

### 4. Bounded channel inputs with pre-validation
**2026.6.35** requires channel adapters and bundled providers to cap and reject oversized/malformed inputs *before* expensive downstream work starts. Applied to browser automation, local tools, workspace reads, and plugin metadata. Prevents hostile payloads from exhausting process memory mid-run.

### 5. Provider account priority with per-agent overrides
**2026.9.3** restructured the provider layer: agents can add/remove accounts, set custom priority order, and clear overrides to fall back to inherited defaults — without disconnecting accounts globally. Provider detection stays passive until the agent explicitly routes.

## What we can use in Lexicon

Ranked by value/effort. Each mapped to a verified `src/` path.

### 🔴 High value / Medium effort

**Reply recovery in runner** → `src/engine/runner.py`  
Lexicon's runner currently has no dedup or recovery guard between a streamed response and its transcript write. Add a checkpoint: on stream close, check if a final reply was already committed before writing again. Pairs with short-term memory flush in `src/engine/memory/short_term.py`.

**Agent-owned skills** → `src/engine/skills.py`  
`skills.py` loads skills globally. Adding a per-`runtime` (agent) override layer — a local skill registry that shadows the global one — follows the Workshop pattern and enables agent-specific skill sets without forking the file. Runtime identity is already tracked in `src/engine/runtime.py`.

### 🟡 High value / Low effort

**Read-only config mode** → `src/shared/config.py`  
A one-pass guard: check `OPENCLAW_CONFIG_READONLY` (or equivalent `LEXICON_CONFIG_READONLY`) on any config-write path and skip the write if set. Already has clear config loading logic. Zero schema change required.

**Provider priority with local overrides** → `src/engine/llm/router.py`  
The router already selects providers by capability. Adding a per-request priority hint (passed from the caller) that can override the global order — without mutating the global state — follows the passive-detection + local-override model. Low risk, high value for multi-tenant setups.

### 🟢 Medium value / Low effort

**Bounded channel inputs** → `src/gateway/server.py`  
Add a max-body-size guard at the gateway ingress (before routing) and a malformed-payload check in `src/gateway/router.py`. A 5–10 line guard that prevents a large or corrupt payload from propagating to the engine.

## My picks for what to spike next

1. **Reply recovery** (`src/engine/runner.py` + `src/engine/memory/short_term.py`) — affects every agent run that involves streaming. A partial stream leaving a corrupt transcript is the most common durability failure; this is the highest-leverage fix.

2. **Read-only config mode** (`src/shared/config.py`) — one env var, one guard, immediate ops value for any deployment that manages config outside the agent. Could land in an hour.

3. **Bounded channel inputs** (`src/gateway/server.py`) — defensive, no behavior change for valid payloads, prevents a class of memory exhaustion issues under adversarial input.
