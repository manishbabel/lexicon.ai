## What's notable (patterns worth porting)

### 1. Gateway stable repair path (2026.7.1)
Repeatedly failing gateways now leave a "stable repair path instead of restarting indefinitely." This is a shift from crash-loop restart to circuit-breaker semantics: after N consecutive failures, the gateway parks in a recoverable wait state with escalating backoff and surfaces a health signal rather than spinning. This prevents runaway restart storms from overwhelming downstream services.

### 2. Quarantine store + crash-recoverable SQLite snapshots (2026.7.2-beta.7)
Before any schema migration or write-heavy operation, OpenClaw now snapshots its SQLite databases into an isolated quarantine store. On crash or schema-upgrade failure the rollback writer restores from the last clean snapshot. Prevents silent data loss when schema upgrades partially succeed.

### 3. Queue dead-letter recovery for channel delivery (2026.7.2-beta.7 + 2026.6.34)
Outbound channel messages that fail during a gateway crash are now tracked in a dead-letter ledger and drained on reconnect. OpenClaw implemented this as a shared ingress drain across Telegram, Signal, Slack, and others. The pattern separates delivery acknowledgement from in-memory queue flushing.

### 4. Plugin/skill provenance warnings (2026.8.1-beta.2)
Plugin installs from unverified sources now require explicit acknowledgement before loading. Each plugin carries a provenance record (origin, hash, signing status). Warnings surface at install time and are logged to the audit trail. This was shipped alongside ClawHub's verified-publisher badge system.

### 5. Structured questions & approvals with option cards (2026.7.2-beta.7)
Agents can now emit structured question envelopes — typed option cards rather than free-text prompts — that route to the appropriate approval channel (web, native, push notification) with fair queuing. The approval response feeds back into the running agent turn without re-queuing. This is the pattern behind "human-in-the-loop" skill confirmation.

## What we can use in Lexicon

Ranked by (value ÷ effort). All file paths verified to exist in `src/`.

### ★★★ Gateway circuit breaker — high value, low effort
**File:** `src/gateway/server.py`

The server's WebSocket accept loop and uvicorn lifecycle currently have no failure-count tracking on the gateway restart path. Adding a circuit breaker (consecutive failure counter + exponential backoff park + `/health` flag) directly mirrors the 2026.7.1 repair-path pattern and prevents crash-loop storms if the upstream LLM router or QMD client is unavailable at startup.

**Spike:** Add a `_consecutive_failures` counter around the lifespan startup block; after 3 failures, sleep with backoff (2s, 8s, 30s) and set a `gateway_degraded` health flag returned by the existing REST health endpoint.

### ★★★ Memory JSONL snapshot before schema/migration ops — high value, medium effort
**File:** `src/engine/memory/manager.py`, `src/engine/memory/episodic.py`

`MemoryManager` reads from short-term JSONL and episodic JSONL. Neither has a snapshot before bulk writes (e.g., compaction, index rebuild). The quarantine-store pattern: before any write-heavy operation, `cp` the JSONL to a `.bak` file; on exception, restore. `EpisodicMemory` in `src/engine/memory/episodic.py` is the most exposed — it accumulates meeting records with no rollback path.

**Spike:** Wrap `EpisodicMemory.append()` and any future compaction path in a snapshot-restore context manager.

### ★★ Queue dead-letter envelope — medium value, low effort
**File:** `src/engine/queue.py`

The existing lane-based FIFO queue (`queue.py`) already handles overflow by summarizing excess messages. The dead-letter pattern extends this: on queue item discard (overflow or worker crash), write the envelope to a dead-letter JSONL in the session data dir. On gateway restart, drain that file back into the queue before accepting new work. Low effort because the queue infrastructure is already in place.

**Spike:** Add a `DeadLetterStore` class alongside `queue.py` that persists dropped envelopes and expose a `drain()` method called from `src/gateway/server.py` lifespan startup.

### ★★ Skill provenance metadata — medium value, low effort
**File:** `src/engine/registry.py`, `src/engine/skills.py`

`AgentRegistry` loads `SkillRegistry` with no origin tracking. Adding a `provenance` dict per skill (source path, hash, load timestamp) to `SkillRegistry` enables future audit logging and a `--unverified` acknowledgement gate for skills loaded from outside `BUNDLED_WORKSPACES`. Mirrors the plugin provenance warning pattern exactly.

**Spike:** Add a `provenance: dict` field to the skill record and log a `WARN` when a skill's source path is not under `BUNDLED_WORKSPACES`.

### ★ Transcript branch index — medium value, high effort
**File:** `src/engine/memory/transcript_index.py`

Session rewind/branching requires the transcript store to support named branch pointers and message-level ancestry. `transcript_index.py` would need a `branch_id` + `parent_message_id` on each entry, plus a branch-checkout method. High effort and only worthwhile if multi-session conversation replay becomes a product requirement.
