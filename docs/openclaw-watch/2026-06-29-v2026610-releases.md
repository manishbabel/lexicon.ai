## What's notable

### 1. Fail-closed security boundaries (v2026.6.6)
Across transcript, sandbox, MCP, browser, and channel paths, unsafe access and timed-out approvals now **reject** rather than degrade gracefully. Previously OpenClaw would silently fall through to an insecure state when a gateway approval timed out; now it raises immediately. The same principle was applied to TLS path validation and artifact sanitization.

### 2. Cron resilience — terminal state persistence (v2026.6.6)
Terminal `timeout` and `cancel` states are now durably persisted per job run rather than lost on restart. Cron expressions with unreachable next-fire times (e.g. impossible day-of-month combinations) are rejected at registration time. ISO timestamps replace raw epoch integers in run output.

### 3. Skill Workshop — versioned skill governance (v2026.6.1)
A proposal lifecycle (submit → approve/reject → quarantine) was added around skill installation. Each proposal carries versioned frontmatter with dated tracking, hash verification, and a rollback path. Scanner integration validates skill files before they become active.

### 4. Same-model retry before cascade (v2026.6.6)
On rate-limit responses, agents now retry within a short back-off window using the **same model** before cascading to an alternative provider. Previously any transient overload immediately triggered a provider fallback, inflating cost and introducing response inconsistency.

### 5. Durable session-transcript SDK contract (v2026.6.10)
A stable SDK surface for plugin access to session transcripts was formalised. Plugins can now subscribe to transcript events via a documented interface rather than reading internal state. The contract survives compaction events without losing position.

## What we can use in Lexicon

Ranked by value × effort (high value first):

### A. Fail-closed gateway approvals — HIGH value / LOW effort
**Pattern**: Any approval gate that times out should return an error, not silently succeed.

**Lexicon file**: `src/gateway/server.py` (WebSocket message dispatch), `src/gateway/session.py` (session lifecycle)

The current gateway dispatches tool-approval responses without a timeout guard. Adding a deadline on the approval wait and raising `PermissionError` on expiry mirrors OpenClaw's hardened path. Scope: ~20 lines.

### B. Cron terminal-state persistence — HIGH value / LOW effort
**Pattern**: Store final run state (timeout/cancel/error) durably in the job record so restarts don't lose run history.

**Lexicon files**: `src/cron/store.py` (`CronJob` model + persistence), `src/cron/scheduler.py` (`_execute_job`)

`CronJob` in `store.py` tracks `last_run` and `errors` but has no `last_run_status` field. Adding an enum field (`ok | timeout | cancel | error`) written atomically after each execution, plus rejecting unreachable cron expressions in `scheduler.py` at job-add time, gives the same durability guarantee. Scope: ~30 lines.

### C. Same-model retry before cascade — HIGH value / LOW effort
**Pattern**: On 429/overload, retry the same model up to N times with exponential back-off before switching providers.

**Lexicon file**: `src/engine/llm/router.py` (`PersonaLLMRouter.resolve`)

Currently the router resolves a provider once. Wrapping the call site (in `src/engine/runtime.py` or a thin retry decorator) with a 3-attempt same-provider retry before re-resolving an alternative would cut unnecessary provider hops. Scope: ~25 lines.

### D. Skill hash verification — MEDIUM value / MEDIUM effort
**Pattern**: Compute a content hash over each skill's SKILL.md at index time and persist it; warn (or refuse) when the on-disk file diverges from the stored hash at runtime.

**Lexicon file**: `src/engine/skills.py` (`_parse_skill_dir`, hot-reload watcher)

The existing hot-reload watcher in `skills.py` re-indexes on any file change but does no integrity check. Adding SHA-256 hash tracking in the skill metadata and surfacing drift warnings gives operators early visibility into unintended skill mutations. Scope: ~40 lines.

### E. Batched transcript chunk embeddings — MEDIUM value / MEDIUM effort
**Pattern**: Accumulate chunks across multiple transcript entries and embed in one batch call rather than one call per chunk.

**Lexicon file**: `src/engine/memory/transcript_index.py` (`TranscriptIndexer`), `src/engine/memory/search.py`

`TranscriptIndexer` currently emits one chunk at a time. A batching wrapper that collects up to N chunks before calling the embedding provider would reduce provider round-trips by an order of magnitude for long meetings.

## My picks for what to spike next

1. **Cron terminal-state persistence** (`src/cron/store.py` + `src/cron/scheduler.py`) — smallest blast radius, immediately actionable, fills a visible gap in job observability. One afternoon.

2. **Same-model retry before cascade** (`src/engine/llm/router.py`) — prevents provider thrash on transient overloads with almost no risk. The back-off logic is self-contained and testable in isolation.

3. **Fail-closed gateway approvals** (`src/gateway/server.py`) — security posture improvement; OpenClaw treated this as a correctness bug, not a feature. Worth landing before any external-facing deployment.
