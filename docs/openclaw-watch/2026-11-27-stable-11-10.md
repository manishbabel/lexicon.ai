## What's notable (patterns worth porting)

### 1. Predict-before-trim context compaction (2026.10.34)
Sessions now compact **before** a predicted context overflow rather than after, and specifically avoid trimming tool-result blocks the provider has already cached. The old approach evicted content that was already in the KV cache — wasting the cache cost and causing unnecessary re-summarization work.

### 2. Scheduled job persistence through config mutations (2026.11.10-beta.3)
Scheduled work now survives session edits, group renames, shared-state changes, upgrades, and Gateway restarts — previously any of these could silently orphan in-flight cron jobs. Companion fix: duplicate cron replies and false failure notices are significantly reduced, suggesting a per-job idempotency guard was added at the execution layer.

### 3. Subagent result durability across restarts (2026.11.10-beta.3)
Completed sub-agent results survive Gateway restarts and remain available while sibling tasks are still running. Previously, a crash mid-orchestration lost all completed child work. The fix implies checkpointing finished sub-agent outputs into durable storage before returning control to the parent.

### 4. Background skill context forking (2026.11.10-beta.3)
Plugins can now fork live conversation context for **hidden background turns** governed by session policy. This decouples async skill work (prefetch, synthesis, indexing) from the foreground conversation, keeping the main context clean and unblocking the user while the skill works in the background.

### 5. SecretRef-backed skill credentials (2026.10.34 + beta.3)
Channel tokens and skill API keys moved from plaintext config into a secret store, with references preserved through settings edits. `SecretRef`-backed values are no longer clobbered when the user edits unrelated settings.

## What we can use in Lexicon

Ranked by value/effort. All file paths verified to exist.

### ★★★ 1. Cron job persistence through config changes — **High value / Low effort**
**Files:** `src/cron/scheduler.py`, `src/cron/store.py`

`CronScheduler._execute_job()` (scheduler.py:177) has no idempotency guard — if APScheduler fires a job twice (e.g., after a jittered restart), both executions proceed and both enqueue agent runs. Add a per-job `running: bool` flag in `CronJob.state` and check it at entry; persist the flag to `CronStore` before and after the run. Also, `start()` currently re-registers all enabled jobs unconditionally (scheduler.py:102–105): jobs whose cron expression changed between restarts silently get the old trigger. Add a job-definition hash to `CronStore` and re-register only on hash change.

### ★★★ 2. Predict-before-trim context compaction — **High value / Low effort**
**File:** `src/engine/context/compactor.py`

`compact_if_needed()` (compactor.py:65) triggers at 85% of budget — this is already proactive, but the compaction candidate selection (compactor.py:113–116) ignores which tool-result blocks the LLM has already processed in earlier turns. Add a `cache_boundary` parameter: messages before the boundary (already seen by the LLM in a prior turn) should only be compacted as a last resort; prefer compacting the uncached middle segment first. This maps directly onto the OpenClaw pattern and avoids paying twice for content already in the provider's KV cache.

### ★★ 3. Subagent result checkpointing — **Medium value / Medium effort**
**Files:** `src/engine/orchestrator.py`, `src/engine/memory/episodic.py`

`Orchestrator` creates one-shot ephemeral runtimes (orchestrator.py:1–16) with no durability. After a sub-agent completes (before returning the result to the Chief), write the `(delegation_id, agent, result)` tuple to `EpisodicMemory`. On retry, check for a cached result before spinning up a new runtime. This is a pure additive change — the orchestrator interface stays the same.

### ★★ 4. SecretRef for skill credentials — **Medium value / Medium effort**
**Files:** `src/shared/config.py`, `src/engine/skills.py`

Skills like `src/engine/tools/web_search.py` currently read API keys directly from config/env. Add a `SecretRef` dataclass to `src/shared/config.py` whose `.resolve()` method reads from an env var, a local secrets file, or a future vault integration — but keeps the reference stable when surrounding config is edited. Update `SkillRegistry` in `src/engine/skills.py` to resolve `SecretRef` fields at skill load time rather than at every call.

### ★ 5. Background skill context forking — **High value / High effort**
**Files:** `src/engine/skills.py`, `src/engine/orchestrator.py`, `src/engine/runner.py`

`SkillRegistry` (skills.py) runs all skill tools synchronously in the main agent loop. A `fork_context()` primitive — analogous to what OpenClaw added for plugins — would let skills like `knowledge-consolidator` and `paper-reader` (workspaces/software-engineer/skills/) run in the background without blocking the foreground session. Requires a lightweight task queue in `src/engine/runner.py` or `src/engine/queue.py` and a session-policy check gating which skills may fork. High value for the multi-workspace Lexicon pattern, but meaningful rearchitecture.
